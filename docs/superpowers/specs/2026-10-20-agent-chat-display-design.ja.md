# エージェントチャット: 作業過程の表示 (段階1)

日付: 2026-10-20 ・ 状態: チャットで設計を承認済み、設計書のレビュー待ち ・ English (正本): [2026-10-20-agent-chat-display-design.md](2026-10-20-agent-chat-display-design.md)

## 目的

エージェントチャットを、ClaudeやOllamaのチャットと同じ見た目・使い勝手にする。全体を3段階に分け、この設計書は段階1を扱う。

1. **応答の表示 (この設計書)**: エージェントがしたこと (思考・本文・ツール呼び出し) を起きた順に見せる。普段は折りたたんでおき、開いて中身を見られるようにする。返答のMarkdownを描画する。
2. メッセージの操作: コピー、直して送り直す、もう一度答えさせる (今あるターン単位の「元に戻す」とつなぐ)。
3. 会話の管理: 名前の変更、削除、検索、書き出し、会話ごとの指示 (システムプロンプト)。

段階2と段階3は、それぞれ別の設計書にする。

段階1が成功したと言えるのは、次の2つを満たしたとき。

- ターンが終わったあと、どのツール呼び出しでも開いて、エージェントが送ったものと返ってきたものを見られる。履歴から開き直した会話でも見られる。
- 見出し・箇条書き・表・コードを含む返答が、整った文章として読める。

## 今の作り

- `ChatMessage` (`madake-agent/src/conversation.rs`) は、本文を1つの`text`と`tool_calls`の並びで持つ。呼び出し1件には、id・ツール名・`input`・`finished`・`is_error`を残している。
- `ChatMessage.vue` は、本文を全部描いてから、その下に呼び出しごとの`ToolChip`を並べる。チップにはツール名と1行の要約しか出ない。
- どのバックエンドも、`AgentEvent::ToolUseFinished`を出す時点でツールの結果を受け取っているが、そのまま捨てている。
  - Claude Code CLI: `parse_user` (`events.rs`) の`tool_result`ブロック
  - Anthropic API・Gemini・OpenAI互換: ツールループの中の`ToolOutcome.content`
  - Copilot CLI: `tool.execution_complete`の行
- 思考もすべて捨てている。`anthropic.rs`と`events.rs`の`thinking_delta`、Claude CLIの応答メッセージの`thinking`ブロックがそれにあたる。
- 返答の本文は`white-space: pre-wrap`で表示していて、Markdownは描画しない。

## 設計

### 1. 会話データ

`ChatMessage`に`blocks: Vec<MessageBlock>`を足す。返答を、起きた順のブロックの並びとして持つ。

```rust
#[serde(tag = "type", rename_all = "snake_case")]
pub enum MessageBlock {
    Text { text: String },
    Thinking { text: String, duration_ms: Option<u64> },
    Tool { id: String }, // tool_calls[].id を指す
}
```

- `TextDelta`が届いたとき、最後のブロックが`Text`ならそこへ足し、そうでなければ新しい`Text`ブロックを作る。`ThinkingDelta`も`Thinking`について同じように扱う。`ToolUseStarted`が届いたら`Tool`ブロックを足す。
- `duration_ms`は、その思考ブロックの最初の差分から最後の差分までの時間。どのプロバイダも思考の時間を返さないので、アプリが測る。
- `text`と`tool_calls`はそのまま残し、今までどおり埋める。段階2・3のコードや古い読み手も、そのまま動く。
- `ToolCall`に`output: Option<String>`と`output_size: Option<u64>`を足す。
  - `output`には結果の先頭8 KBを残す。切る位置はUTF-8の文字の切れ目に合わせる。
  - `output_size`には、結果全体のバイト数を入れる。
  - 2つが違うとき、画面に「…残り N KB は省略」と出す。
- 足すフィールドは、どれも`#[serde(default, skip_serializing_if = ...)]`にする。そのため、`CHAT_FORMAT_VERSION`は2のまま変えない。
  - 古いビルドが新しいファイルを読んでも、知らないフィールドは無視する (`deny_unknown_fields`はどこでも使っていない)。古いビルドが保存し直すとそのフィールドは消えるが、それは許容する。
  - `blocks`の無いメッセージ (この変更より前に保存した会話) は、今までどおり、本文のあとにツールの手順を並べて表示する。

### 2. イベント

- `AgentEvent::ToolUseFinished`に`output: Option<String>`を足す。各バックエンドは、すでに持っている結果をここに入れる。

  | バックエンド | 結果の取り出し元 |
  |---|---|
  | Claude Code CLI | `tool_result.content`。文字列か、テキストブロックの配列をつないだもの |
  | Anthropic API・Gemini・OpenAI互換 | `ToolOutcome.content` |
  | Copilot CLI | `tool.execution_complete`の行に結果の文字があればそれ (今ある`text_of`の規則で取る)。無ければ`None` |

- `AgentEvent::ThinkingDelta { text: String }`を新しく足す。追加の設定をしなくてもプロバイダが思考を送ってくるところでだけ出す。

  | バックエンド | 思考の取り出し元 |
  |---|---|
  | Claude Code CLI | `stream_event`の`thinking_delta`。本文と同じく、最後の応答メッセージにある`thinking`ブロックは出し直さない |
  | Anthropic API | `thinking_delta` |
  | OpenAI互換 (Ollamaなど) | モデルが送ってきたときの`delta.reasoning_content`か`delta.reasoning` |
  | Gemini | 対象外 (`includeThoughts`を有効にする設定が要る) |
  | Copilot CLI | 対象外 |

- 8 KBへの切り詰めは、`Conversation`がイベントを記録するときに行う。イベント自体は結果を全部運ぶ。実行中のターンが、メッセージより長く結果を持っておく必要は無いため。

### 3. 画面の部品

`ChatMessage.vue`は`blocks`に沿って部品を置くだけにする。`src/components/chat/`に足す部品は次のとおり。

| 部品 | 役目 |
|---|---|
| `ChatMarkdown.vue` | 本文のMarkdownを描画する。コードブロックには言語名とコピーボタンを付ける |
| `ThinkingRow.vue` | 折りたたんだ「N秒考えました ›」の行。開くと、左に線を引いた中に思考の文を出す |
| `ToolGroup.vue` | 続けて並んだツール呼び出しを1行にまとめた「ツールをN件使いました ›」の行。開くと、左に線を引いた中に手順を並べる |
| `ToolStep.vue` | 手順1行 (状態のアイコン・ツール名・要約・›)。開くと「入力」(整形したJSON) と「結果」の欄を出し、それぞれにコピーボタンを付ける。切り詰めたときはその案内も出す |

- `ToolChip.vue`は`ToolStep.vue`に置き換える。
- 続けて並んだ`Tool`ブロックをまとまりに分ける処理は、`stores/chat.ts`の純粋な関数`groupBlocks(blocks)`にする。単独でテストできるようにするため。`Thinking`か`Text`のブロックが来たら、まとまりはそこで終わる。

開閉の動き (Claudeと同じ):

- ターンの応答中は、まだイベントを受け取っているまとまりや思考の行を開いておく。ターンが終わったら、どちらも閉じる。
- 利用者が自分で開いたり閉じたりした行は、パネルを開いている間はその状態を保つ。会話には保存しない。
- 失敗した手順を含むまとまりは、閉じたままでもまとめ行を赤くする。開かなくても失敗が分かるようにするため。
- 実行中の手順は、今のチップと同じく、✓の代わりに回転するアイコンを出す。

見た目は、`MadakeCAD.pen`の承認済みの見本に合わせる。折りたたんだ状態は`AIチャット 作業過程(折りたたみ)`、開いた状態は`AIチャット 作業過程(展開)`。

### 4. Markdown

- ライブラリは`markdown-it`をバージョン`15.0.2`に固定して使う。15.0.3はこの設計書の4日前 (2026-10-16) に公開されたばかりなので、1つ前の版にする。`@types/markdown-it`は開発用の依存に入れる。
- 描画するもの: 見出し、箇条書き、番号付きリスト、表、太字と斜体、インラインコード、コードブロック、引用、区切り線。
- 段階1で描画しないもの: コードの色分け (言語名だけ出す)、数式、生のHTML。
- 安全のための対策: アプリはTauriの中で`"csp": null`のまま動いているので、モデルの出力を動くHTMLにしてはならない。
  - `html: false`にする。返答に含まれる生のHTMLは、文字として表示する。
  - リンクは`http:`と`https:`だけを残す。押すと`@tauri-apps/plugin-opener`でOSのブラウザで開き、アプリの画面は移動しない。それ以外のスキーム (`javascript:`、`file:`、`data:`) は、ただの文字として表示する。
  - 画像`![alt](url)`は、altの文字を表示したリンクとして描画する。返答によってアプリが外部の内容を読み込まないようにするため。
- 応答中は、差分が届くたびに描画し直す。閉じていないコードブロックは、それまでに届いた文字の終わりまでをコードブロックとして表示する (markdown-itの標準の動き)。

### 5. エラーの扱い

- ツールの結果がUTF-8として正しくないことは起きない。どの取り出し元もJSONの文字列なので、`output`は必ず文字になる。
- 結果が8 KBより長いとき、保存する`output`は8 KBより前の最後の完全な文字で終わり、`output_size`には実際の大きさを残す。
- もう無いメッセージに対する思考やツールのイベント (例えば、ターンの途中で会話を消したとき) は、今の本文の差分と同じく無視する。

## テスト

このリポジトリでは、テストが仕様書そのものになる。テストにはそれぞれ英語と日本語の仕様文を付け、`scripts/gen_spec.py`で`docs/13-specification(.ja).md`を作り直す。

- Rust:
  - どのバックエンドも、ツールの結果を`ToolUseFinished.output`に入れる。
  - Claude CLIとAnthropicは`ThinkingDelta`を出す。OpenAI互換は`reasoning_content`と`reasoning`のどちらでも出す。Geminiは出さない。
  - `Conversation`は`blocks`を起きた順に作り、続けて届いた差分は1つにまとめ、思考の時間を測る。結果は8 KBで文字の切れ目に合わせて切り、`output_size`を残す。
  - `blocks`と`output`の無い会話ファイルも、今までどおり読み込めて使える。
- Vitest:
  - `groupBlocks`は、続けて並んだツールをまとまりにする。
  - まとまりは応答中に開き、終わったら閉じる。利用者が開いた・閉じた状態は保たれる。
  - 失敗した手順があると、まとまりが赤くなる。
  - Markdownの安全対策: 生のHTMLは文字になる、`javascript:`のリンクはリンクにならない、画像はリンクになる、リンクはopener経由で開く。
  - コピーボタンで、入力・結果・コードブロックがコピーされる。
  - `blocks`の無い古いメッセージも表示できる。
- アプリでの確認: Claude Code CLIで図面を編集するターンを実行し、思考の行・ツールのまとまり・手順を開いたり閉じたりする。そのあと会話を履歴から開き直し、結果が残っていることを確かめる。

## 出し方

PRは2本に分ける。どちらも`master`向けで、積み重ねはしない。

- **PR A: 会話データとイベント (Rustだけ)**。`MessageBlock`、`ToolCall.output`、`ToolUseFinished.output`、`ThinkingDelta`、各バックエンドの変更、テストを含む。画面は新しいフィールドを使わないので、PR Aだけをマージしても見た目は変わらない。
- **PR B: 画面**。新しい部品、markdown-it、6つのロケールファイルの文言、このブランチにコミット済みの見本2枚 (`05360be`) を含む。PR Aの後に作り、説明に「#A を先にマージ」と書く。
