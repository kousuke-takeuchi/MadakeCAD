# MCP のピン操作ツール: ピン名で配線する

日付: 2026-10-22 · 状態: チャットで設計承認済み、設計書のレビュー待ち · 英語版 (正): [2026-10-22-mcp-pin-tools-design.md](2026-10-22-mcp-pin-tools-design.md)

## 目的

アプリ内エージェントが、座標を自分で計算せずに、正しくつながった配線図を描けるようにする。

背景: [エージェント作図の比較](../../internal/research/2026-10-22-agent-drawing-comparison.ja.md)。エージェントは AOGU CoCo の配線図 (A3 3 枚) を約 40 分で描いた。ピンの位置を知っているスクリプトは、同じ図面を 4.6 秒で描いた。エージェントの時間の大半は、ピン座標の手計算 (ブロックの 5mm 丸め、外形の 2.5mm 外側のピン、回転と反転) に使われた。

成功の目安: エージェントが同じシートを 40 分よりずっと短く、少ないツール呼び出しで描き直す。座標の誤りで未接続になるピンが出ない。

## 今あるもの

- MCP の作図ツールは、低い段階の `place_symbol` (x/y に置く) と `draw_wire` (点の列) だけ。置いた部品のピン位置を返すツールは無い。
- ピン位置の計算は本体にある。`madake-core/src/netlist.rs` の `pin_positions(inst, def)` が反転、回転、平行移動をかける。`madake-core/src/block.rs` の `block_symbol` / `block_box` が、ブロックのピンと丸めた大きさを作る。
- `PinDef` は `number`、`name`、`at`、`dir` (回転 0 のときの上下左右) を持つ。
- リポジトリの外の手順書 (`~/.claude/skills/drawing-madakecad-wiring`) には、この計算をする Python の補助スクリプトがある。しかし、アプリ内エージェントはシェルを使えないので、補助スクリプトを動かせない。

## 設計

### ピン指定

ピンは `"<参照記号>.<ピン>"` の形で書く (例: `"U1.SDA"`、`"J1.2"`)。**最後の** `.` で分けるので、参照記号に `.` が入っていても扱える。`<参照記号>` の代わりに entity id (UUID) も書ける。`<ピン>` はピン番号で照合し、番号が一致しなければピン名で照合する。

### 1. `get_pins`

- 入力: `sheet_id` (他のツールと同じく省略できる)、`reference` か `entity_id` のどちらか。
- 出力: 一致した部品ごとに 1 件 (かみ合わせの組のように、同じ参照記号の部品が複数あることがある)。
  - `entity_id`、`reference`、`symbol_id`
  - `bbox`: 用紙上の外形 (ブロックは 5mm 丸めの後)
  - `pins`: `number`、`name`、`x`、`y`、`dir` (回転と反転の後)

### 2. `connect_pins`

- 入力: `sheet_id`、`from`、`to` (ピン指定)、`via` (経由点、省略できる)、`color`、`sq`、`length_m`、`part_no` (意味と既定値は `draw_wire` と同じ)。
- 出力: 作った配線の `entity_id`、実際に使った `points`、`revision`。
- 頂点はすべて、ピンの座標か `via` の点から作る。斜めの線分は作らない。
- `via` が無いときは、2 つのピンの向きで引き方を決める。

  | 両端の向き | 引き方 |
  |---|---|
  | どちらも左右向き | Z 字: 水平、垂直、水平。曲がる x は中央 |
  | どちらも上下向き | Z 字: 垂直、水平、垂直。曲がる y は中央 |
  | 左右向きと上下向き | L 字。各端は自分の向きへ出る |
  | 一直線に並んでいる | 直線 1 本 |

- 曲がる位置は 2.5mm のグリッドにそろえる。
- `via` があるときは、`from`、各 `via`、`to` の順に通る。隣の点とそろっていない区間には、水平を先にした角を 1 つ足す。
- 部品を避ける処理はしない。重なりは `get_tidy_metrics` で見つけ、エージェントが `via` を足して直す。

### 3. `place_mate`

- 入力: `sheet_id`、`x`、`y`、`orientation` (`horizontal` | `vertical`)、`male_side` (`first` | `second`: 左か上の部品がプラグかどうか)、`reference`、`value`。
- `connector_plug` と `connector_socket` を 5mm 離して向かい合わせに置く。外側の接続点は 2.5mm グリッドにのり、2 つの外形は接するだけになる。`reference` は両方に、`value` はソケット側に付ける。同じ参照記号のプラグとソケットは `erc.duplicate_reference` にならない。
- 出力: 2 つの entity id と、外側の 2 つの接続点 (`first`、`second`)。

### 4. `place_symbol` がピンを返す

`place_symbol` は今の `entity_id` と `revision` を残し、`get_pins` と同じ形の `pins` を足す。今の呼び出し側はそのまま動く。

### コマンドと取り消し

編集はすべて今の `Command::AddEntity` を通る。そのため、取り消し、やり直し、ターン単位の取り消しは今と同じように効く。`place_mate` は 2 つの追加を 1 つのまとまりとして実行するので、1 回の取り消しで組ごと消える。

### エラー

次の場合は何も作らない。エージェントが自分で直せるように、メッセージに候補を添える。

| 起きたこと | メッセージに添えるもの |
|---|---|
| 参照記号が見つからない | シート上の似た参照記号 |
| ピンが見つからない | その部品のピン (番号と名前) |
| 同じ参照記号の部品が複数あり、どれにもそのピンがある | それぞれの entity id (`"<entity_id>.<ピン>"` で指定し直す) |
| `from` と `to` が同じピン | (なし) |

### システムプロンプトと文書

- `madake-agent/src/knowledge.rs` の `WORKFLOW_RULES` に短い決まりを足す: 配線図では、部品を `place_symbol` / `place_mate` で置き、位置を `get_pins` で読み、`connect_pins` で配線する。ピン座標を手で計算しない。
- `docs/10-automation-api.md` と `.ja.md` に 3 つのツールを書く。
- リポジトリの外の手順書にも、アプリ内エージェント向けに同じことを書く (PR には含めず、別に更新する)。

## テスト

`madake-mcp/tests/drawing_tools.rs` を新しく作る。仕様の決まりどおり、`///` の英語と日本語の行を付ける。

- `get_pins`: 回転と反転をしたシンボル、ブロックの名前付きピン、同じ参照記号の部品 2 つ。
- `connect_pins`: Z 字 (水平)、Z 字 (垂直)、L 字、直線、`via` あり。曲がる位置が 2.5mm グリッドにのる。配線の後、`run_verification` で、つないだピンが未接続として出ない。
- エラーの 4 種類。
- `place_mate`: 2 つの向きと 2 つの `male_side`。1 回の取り消しで組ごと消える。
- `place_symbol` が `pins` を返す。

その後 `python3 scripts/gen_spec.py` を実行する。最後にアプリを開発モードで動かし、エージェントに AOGU の 1 シートを描かせて、所要時間とツールの呼び出し回数を前回と比べる。

## 届け方

`feature/mcp-pin-tools` から PR を 1 本出す。ツール、テスト、システムプロンプトの決まり、文書、比較の記録を含める。

## 決定記録

- 2026-10-22: 配線の形は直角の L 字と Z 字だけ。部品は避けない (ユーザーが 3 案から 1 を選んだ)。結果が予想しやすく、作る量も小さい。重なりはエージェントが `via` で直す。
- 2026-10-22: 案 A (低い段階のツール 3 つ) を選んだ。案 B (図面全体を 1 回で描く宣言型のツール) と案 C (アプリ内エージェントに Python の補助スクリプトを動かさせる) は選ばなかった。A は今のツールと同じ粒度なので、部分的な手直しにも使える。C はシェル禁止を弱める。
- 2026-10-22: 実機での試行の後、まとめて送る形を足した: `connect_pins.connections[]` と `place_mate.mates[]`。それぞれ1回の編集でundo一発、全部できるときだけ行い、誤りは何番目かを知らせる。エージェントは1本ずつのツールを一度も呼ばず、座標を手で計算した`execute_commands`を最大181件まとめて送っていたため。
- 2026-10-22: プラグにもソケットと同じ参照記号を付ける (ユーザーの選択)。以前はプラグを空欄にしていたため、組ごとに `erc.empty_reference` が出て (実機の試行で 111 件)、エージェントはそれが想定どおりかを確かめるために ERC のソースを読んでいた。ERC は、同じ参照記号のプラグとソケットを、リレーのコイルと接点と同じように扱う。
- 2026-10-22: かみ合わせの間隔を 3.5mm から 5mm にした。3.5mm では外側の接続点がグリッドから外れ (x+11)、外形どうしも重なるため、整頓指標が組ごとに重なり 1 件とグリッド外 2 件を数えていた (実機の試行で重なり 15/42/13、グリッド外 30/84/26、すべて組によるもの)。
