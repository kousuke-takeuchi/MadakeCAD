# A0参考図面を領域ごとに再現する

日付: 2026-11-14 · 状態: 設計はチャットで承認済み、仕様書はレビュー待ち · 英語(正本): [2026-11-14-a0-reference-reproduction-design.md](2026-11-14-a0-reference-reproduction-design.md)

## 目的

社外秘の参考図面1枚(A0横、以下**参考図面**)をMadakeCADで描き直す。結果は**見た目が同じ**で、**電気的に正しい**こと。作業で見つかったMadakeCADのギャップは全て埋める。

参考図面はリポジトリに入れない。`docs/references/`(git管理外)に置き、どのファイルかは`docs/references/README.md`に書く。この仕様書を含め、コミットする文書は参考図面を一般的な言葉だけで説明する。`scripts/audit_confidential.py`は常に指摘0件を保つ。

成功の条件:

- A0横1枚のMadakeCADプロジェクトができる。書き出したPDFを同じ解像度で参考図面に重ねたとき、部品の位置、配線の経路、配線の色、文字の内容と位置、図枠、表題欄、改訂欄が一致する。
- そのプロジェクトのネットリストに、未接続のピンと宙に浮いた配線が無い。参考図面が意図して開放している箇所は除く。
- 見つけたギャップは全て台帳に記録し、ユーザーが残すと合意したもの以外はMadakeCAD側で解消する。最終的に未解消0件を目指す。
- プロジェクトは絵ではなく、検証とシミュレーションの入力として使える電気モデルである:
  - 部品は全て、ピンと種別を持つシンボルかブロックで描く(ヒューズはヒューズ、電源は電源)。図形だけでは描かない
  - 参考図面に書かれた定格は、文字と同時に属性にも入れる
  - 配線は全て、色と線径を属性で持つ。線径は品番の凡例から引く
  - 参考図面に無い値は空欄のまま残す。推測では埋めない

対象外:

- 書体。参考図面はCADのストロークフォントで、MadakeCADは自分の書体を使う。文字の高さ、基準位置、置き場所は合わせるが、字形は合わせない。
- グリッドより細かい位置。座標は2.5mmグリッドへ丸め、丸めの誤差は許容する。
- アプリ内で以前に試した図面(7シート、57エンティティ)。エージェントとの会話を後で検証するための退避としてだけ残し、流用しない。
- シミュレーションの拡張。足りない定格を入力し、保護機器の容量不足などの問題を見つける作業は次のサブプロジェクトとし、設計、仕様、計画を別に行う。そこでの未決事項: 基板上の回路の扱い(DC動作点で解くか、ブロックの入出力モデルにするか)、突入電流などの過渡、負荷電力を入力するUI。

## 現状(確認済み)

- 参考図面のPDFはA3の1ページで、A0図面を縮小したもの。全てベクタで、文字はアウトライン化されているため文字列は取り出せない。線の形状、色、太さは取り出せる。
- 以前の再現(別の参考図面のシート1)で方式が決まっている。`docs/references/repro/`の決定的なPythonスクリプトがLink APIへCommandを送り、一般化したギャップは`docs/internal/specs/reproduction-gaps.md`(G1〜G23)へ書く。
- インストール済みアプリはポート9310で待ち受ける。開発ビルドは`MADAKE_MCP_PORT`で別ポートにできる。
- 以前の試行とその会話は`docs/references/repro/a0-attempt1/`(git管理外)に保存済み。

## 方法

### 1. 用紙と座標

A0横1枚に原寸で描く。PDFのポイントから用紙のmmへは、倍率1つ(A3からA0、約2.83倍)とオフセット1つで変換する。どちらも参考図面の図枠の角から測る。変換後の位置は2.5mmグリッドへ丸める。

### 2. 正解データ

- 形状: 参考図面に`pdftocairo -svg`を掛け、スクリプトでパスを線分(色と太さ付き)にまとめ、領域別のJSONとして`docs/references/repro/a0/truth/`へ書く。
- 文字: 600dpiの切り出し画像から読む。確信を持って読めない文字は一覧にしてユーザーに確認する。推測では埋めない。

### 3. 再現スクリプト

`docs/references/repro/a0/`に、領域ごとのPythonファイルと実行スクリプトを置く。実行スクリプトは**ポート9320の開発ビルド**のLink APIへCommandを送る。作業中に足した機能をすぐ使うためである。決定的で、空のプロジェクトから何度でも再実行できる。インストール済みアプリ(9310)は使わない。

### 4. 比較

実行のたびにシートをPDFへ書き出し、参考図面と同じ解像度で画像にして、領域ごとの重ね差分画像を出す。領域の合格条件:

- 参考図面のその領域にある部品、配線、接続点、文字が、全て対応する位置にある
- 配線の色が一致する
- `GET /verify`が、その領域で意図したもの以外の未接続ピンと宙に浮いた配線を報告しない
- 重ね差分と切り出し画像の目視で、重なりと読めない文字が無い

### 5. ギャップの扱い

- ギャップには`docs/internal/specs/reproduction-gaps.md`と日本語版で次の番号(G24以降)を付け、一般的な言葉で書く。
- ギャップは1件ごとに別ブランチで解消する。プロジェクトの規則に従う: 仕様または短い設計を先に書く、計画、TDD、テストに英日の仕様文を付ける、`python3 scripts/gen_spec.py`で再生成、全ての編集は`madake-core`の`Command`を通す。
- UIの見た目が変わる機能は、先に`MadakeCAD.pen`でデザインする。
- ギャップを残すのはユーザーが合意したときだけ。既定は解消する。
- 顧客固有の内容(ロゴ、社名、品番)はリポジトリへ入れない。ユーザーデータ(`~/MadakeCAD/templates`、プロジェクトファイル)か`docs/references/`へ置く。

### 6. 領域の順序

1. 図枠、表題欄、改訂欄
2. 〜7. 図面そのものの6つの領域。順序はgit管理外の`docs/references/repro/a0/NOTES.md`に書く

領域1を最初にするのは、座標の変換がここで決まるためである。

## 予想されるギャップ

ここには書かない。参考図面に必要でMadakeCADに無いものは、領域を描くたびに、一般的な言葉でギャップ台帳へ記録する。

## リスク

- アウトライン文字の読み違い。対策: 600dpiの切り出しと、疑わしい文字列の一覧をユーザーへ出す。
- 早い領域のために作った機能が後の領域に合わない。対策: ギャップを設計する前に、他の領域に同じ要素が無いか確認する。
- 機密用語の混入。対策: コミットの前に毎回`scripts/audit_confidential.py`を実行する。
