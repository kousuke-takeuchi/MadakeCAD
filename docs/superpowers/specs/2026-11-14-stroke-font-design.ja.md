# 図面の文字のストロークフォント(KST32Bを同梱)

日付: 2026-11-14 · 状態: 設計はチャットで承認済み、仕様書はレビュー待ち · 英語(正本): [2026-11-14-stroke-font-design.md](2026-11-14-stroke-font-design.md)

## 目的

図面の文字を、システムのサンセリフ書体ではなく、CADのストロークフォント(線でできた字)で描けるようにする。MadakeCADで作る図面に、産業図面で使われる書体を持たせるためである。ライセンスが許すストロークフォントを同梱し、最初から使えるようにする。

これは、A0参考図面の再現(`2026-11-14-a0-reference-reproduction-design.ja.md`)の領域1に残った最後の差、つまり書体を埋める。参考図面そのもののフォントは入手できないので、目指すのは同じ種類の文字(高さ・幅・字間の合ったストローク文字)であり、字形の完全な一致ではない。

成功の条件:

- プロジェクトでストロークフォントを選べる。選ぶと、そのシートの全ての文字(図枠、表題欄、改訂欄、参照記号、型番、配線注記、ネットラベル、注記、帳票シート)が、SVG書き出し・PDF書き出し・キャンバスでそのフォントになる。
- KST32B version 3.0を、元の説明文書と一緒に同梱し、サードパーティのライセンス一覧に載せる。
- 図枠テンプレートは、フォントの全角英数字を指定でき、セルごとに字間を指定できる。
- ストロークフォントを選んでいないプロジェクトは、これまでと完全に同じ出力になる(既存の完全一致テストは変更しない)。
- ストロークフォントを選んでも、ピン・シンボルの外形・配線は一切動かない。

対象外:

- フォントを選ぶUI(後のUIのサブプロジェクト。設定はCommand API・CLI・スクリプトから行う)。
- シンボルエディタ・図枠エディタ・図枠テンプレートのプレビューのキャンバス(システムの書体のまま)。
- DXF書き出し(文字はTEXT要素のまま)。
- フォントの追加。登録表は、ライセンスの合う別のフォントを足せる形にするが、今回入れるのはKST32Bだけ。
- ストロークフォントで作ったPDFの文字検索(文字が線になるため)。

## 現状(確認済み)

- SVG: `madake-core/src/svg.rs`は36か所で`<text>`を書く。共通の書き手は`text_family_el` / `text_el` / `text_weight_el`で、残りは要素を直接書いている。`report_sheet.rs`と`terminal_diagram.rs`にも1か所ずつある。PDFはSVGから変換する(`pdf.rs`)。
- キャンバス: `src/canvas/textSize.ts`(`setDrawingFont`、`drawingText`)が`src/canvas/renderer.ts`の共通の経路。エディタ系のキャンバスの一部は`fillText`を直接呼ぶ。
- 文字幅は`tidy::text_width`(半角1文字 = 高さ×0.6、全角 = 高さ×1.0)と、そのTypeScript側の`textWidthMm`で見積もる。この見積もりは、ラベルの配置だけでなく形状にも使われる。ブロックシンボルはピン名から自分の大きさを決める(`block.rs`)。
- プロジェクトの設定は`set_project_meta`で変える。`FORMAT_VERSION`は20。
- `scripts/gen_licenses.py`が`docs/internal/third-party-licenses.md`を生成し、「フォントは同梱しない」と記している。
- KST32B 3.0(配布アーカイブで確認): 7,514字(ASCII、半角カナ、ISO 8859-15、JIS X 0208の第1水準と第2水準)。30×32の格子上の直線で字を定義するプレーンテキスト形式`CSF/1`で、半角の字は左の15列を使う。説明文書は、フリーウェアであること、使用・配付・改変・再配付が自由であること、無保証であることを述べる。著作権表示は copyright (C) 2017 Saka.N。

## 設計

### 同梱フォントと登録表

- `src-tauri/resources/stroke_fonts/kst32b/`に`KST32B.TXT`、`KST32B.RDM`、`KST32B.MAN`を変更せずに置く。
- `madake-core/src/stroke_font.rs`がデータを埋め込み(`include_bytes!`)、登録表を公開する: `fonts() -> &[StrokeFontInfo { id, name, license_note }]`と`font(id) -> Option<&StrokeFont>`。idは`kst32b`だけ。フォントは初めて使うときに1回だけ解析する。
- `gen_licenses.py`に「同梱フォント」の表を足す。フォント名、作者、版、説明文書から引用したライセンスの文、リポジトリ内の説明文書のパスを載せる。

### 設定

`Project.text_font: Option<TextFont>`、`TextFont { id: String, latin: Latin }`、`Latin = half | full`(既定`half`)。`None`(既定)は今までどおりシステムの書体。`set_project_meta { text_font }`で設定する(知らないidは拒否)。プロジェクトの形式は21になる。

`half`はASCIIをフォントの半角の字で、`full`はASCIIをフォントの全角の字(幅が2倍)で描く。

図枠テンプレートは、自分の文字(表題欄のセルと改訂欄)について`text_latin: half | full`で英数字の字を上書きできる。セルは`spacing`(各文字の送りに掛ける倍率、既定1)を指定できる。

### 大きさと寸法

文字のフォントサイズ`s`の意味は変えない。字の格子は、半角の大文字の高さが`0.72 × s`(`text_size_is: cap`が既に使っている比)になるよう縮尺する。KST32Bの大文字は格子25行ぶんなので、格子1単位は`0.72 × s / 25`。半角1文字の送りは15単位(`0.432 × s`)、全角は30単位(`0.864 × s`)。線幅は`0.07 × s`で、0.13mmを下回らない。線端と角は丸。

アンカー(`start`、`middle`、`end`)と回転は`<text>`と同じに振る舞う。ベースラインは大文字が立つ格子の行。

### 形状は動かさない

`tidy::text_width`と、そこから大きさを決めるもの(ブロックの外形、ピンの位置、ラベルの配置、重なりのメトリクス)は変えない。`latin: half`ならストロークの字は必ず見積もりより狭いので、文字は見積もりが確保した場所に収まる。正確な幅が要り、他が依存しないところ(図枠のセルを幅に収める処理、枠付きセルの枠、改訂欄)では、ストロークフォントが有効なときにその実幅を使う。

### 描画

- `stroke_font.rs`: `layout(text, size, latin, spacing) -> Option<StrokeText { polylines, width }>`。字形の無い文字が1つでもあれば`None`で、その文字列はシステムの書体で描く。
- SVG: `<text>`を書く箇所を全て1つの関数に通す。ストロークフォントのときは、その文字列の全ての線を持つ`<path>`を1つ書く(`fill="none"`、`stroke-linecap="round"`、`stroke-linejoin="round"`)。`<text>`に付くはずだった変換はそのまま付ける。太字は線を1.5倍にする。
- PDF: 何もしない(SVGから変換される)。
- キャンバス: フロントエンドが同じ`KST32B.TXT`を同梱し(そのままのアセットとして読み込む)、同じ規則のTypeScriptの解析と配置を持つ。プロジェクトのフォントが設定されていれば`drawingText`が線で描く。読めないほど小さい文字は今までどおり描かない。

### 互換性

- `text_font`が無い: 全ての書き手が今の経路を通る。出力は同一。
- 形式20を読むビルドは、形式21のファイルを版番号で断る。`text_font`は`None`のとき書き出さない。

## テスト

RustとVitestで、英日の仕様文を付けて書く:

- 解析: `CSF/1`の全てのバイトの種類、ある字の線、字の総数、半角と全角の送り
- 配置: 文字列の幅、アンカー、字間、ASCIIの`full`への対応、字形の無い文字では`None`
- SVG: 文字が、正しい位置と縮尺の`<path>`1つになる。回転が保たれる。太字が太い。知らない文字を含む文字列は`<text>`のまま。ストロークフォント無しでは既存の完全一致テストが無編集で通る
- 形状: ブロックと配線のあるシートで、ストロークフォントの有無によってネットリスト・ピンの位置・`verify`の結果が変わらない
- 図枠: `text_latin`、`spacing`、収める処理、枠がストロークの幅を使う
- コマンドと形式: `set_project_meta { text_font }`の往復、知らないidの拒否、形式20→21
- キャンバス: 同じ入力に対して、解析と配置がRustと同じ数値を返す
- ライセンス一覧: 生成した文書に同梱フォントが載る

通しの確認: 再現の領域1を`text_font`を設定して描き直し、表題欄の重ね比較を確かめる。結果はgit管理外のメモに記録する。

## リスク

- SVGの`<text>`の書き手の取りこぼし。対策: 文字を持つ全ての種類のエンティティを使ったシートをストロークフォントで書き出し、`<text`が残らないことを確かめるテスト(フォントに無い文字を含む文字列を除く)。
- RustとTypeScriptの配置の食い違い。対策: 数値のテストケースを共有する。
- フロントエンドの配布物の大きさ(フォントデータで+350KB)。許容する。
- 大きい文字での字の粗さ(30×32の格子上の直線)。許容する。このフォントの性質である。
