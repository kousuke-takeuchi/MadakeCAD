# Standards & Output

[日本語](04-standards-output.ja.md)

Drawings comply with Japanese industrial conventions (JIS) and are rendered identically on screen and in print-quality vector output.

## Available

- **JIS drawing frame**: paper sizes A4–A0, landscape/portrait; border with zone references (columns numbered, rows lettered); title block (drawing number, title, scale, date, designed/drawn/checked/approved, company, revision mark)
- **Frame editor**: the frame template dialog's *Edit…* / *New (from a copy)* opens a graphical editor on the template JSON (the format does not change). Tools: select, line and rectangle (title-block rules), text (fixed text), placeholder (a bind such as `{project.name}`, replaced by the real value on output), title cell (a sized cell with its border), logo frame and zones. Placeholders are picked from a searchable list (project / sheet / revision and title block); the canvas can hide them or show the current project's real values. The 1 mm grid snaps (Alt turns it off) and Shift keeps lines horizontal or vertical. The right panel edits the selected item, or with nothing selected the whole frame (names, paper, margin, zone divisions and labels, title-block corner/size/row height, revision rows and column widths). `⌘Z`/`⇧⌘Z` inside the editor are its own undo and never touch the drawing's history. The pre-save check counts unknown placeholders and items outside the frame (both still save) and blocks what the core refuses (a cell with both or neither text and bind, a zero text height, revision column widths that do not add up to the title block width). Saving writes `~/MadakeCAD/templates/frames/{id}.json`; bundled frames cannot be overwritten, so they and copies are saved under a new id (*Save as…*). Every sheet that uses the frame is drawn with the saved version from then on — canvas, SVG and PDF
- **Frame templates (plot frames)**: the frame, the title block and the revision table are data, not code — a JSON template describes the margin, the zone label styles, the title-block cells (rule lines plus cells that carry either fixed text or a **bind**) and the revision block. Binds are resolved while drawing: `{project.name}`, `{project.no}`, `{sheet.no}`, `{sheet.total}`, `{sheet.name}`, `{rev.latest}`, `{title_block.*}` and the aliases `{date}` `{scale}` `{designer}` `{approver}`. A bind nobody knows resolves to empty instead of breaking the sheet. `{project.name}` and `{project.no}` are supplied by `Project.name`/`Project.no`; the **Project information** dialog (Schematic tab → Edit group) or the `set_project_meta` command set them, and the same command writes the title-block fields (`{title_block.company}`, `{title_block.drawing_no}`, `{title_block.title}`) to every sheet at once (G16). The project number is three-state: leave the field out and it stays as it is, send `null` (or empty the box in the dialog) and it goes back to *unset* — never to an empty number — and undo restores whichever of the two it was. Two templates ship — `jis-a3` (byte-identical to the previous hard-coded output) and `jis-a4-portrait`; your own go in `~/MadakeCAD/templates/frames/`. The picker (Admin tab → Templates group → *Frame template*, also on the Project tab) shows a live preview of the sheet you are on, with `{bind}` in blue over the fields that would come out empty. *This project* switches every sheet of the drawing in **one command** — canvas, SVG and PDF alike, and one `⌘Z` takes it back — while *Global default* only sets the frame new projects start with. The paper size never changes with the template, and neither do the zone divisions: those belong to the sheet, so swapping frames can never move a zone address that a cross-reference points at. To change a sheet's own paper size or orientation after it was created, use the **Paper size** dialog (Schematic tab → Edit group) or the `set_sheet_paper` command (G15) — existing entity coordinates are kept exactly as drawn and the zone divisions stay the sheet's own (a paper change never rewrites them either), and anything left outside the new paper is reported as an ERC Warning (`erc.outside_paper`) rather than being moved or deleted
- **Revision table**: ISO 7200-style block directly above the title block — columns mark / date / description / approved, oldest row at the bottom, up to six rows on the frame (older rows stay in the file); the title-block revision mark always follows the newest row. Edited in the revision dialog (Schematic tab → Edit group → *Revisions*), so saving is a single undoable command
- **Sheets & zones**: configurable zone grid per sheet; zone addresses are what cross-references point at
- **Cross-sheet references**: net labels of the same name are one project-wide net; each label carries the address of its counterpart on the other sheets (`/2.B3`, several listed side by side) on screen, in SVG and in PDF. Selecting a label lists the destinations in the properties panel, and clicking one jumps to that sheet and zooms to the matching label. Project-wide nets also drive the wire list and ERC, so a net spanning two sheets is reported once. The same address form covers **devices**: any reference designator drawn on more than one sheet gets the same note beside every instance it has, naming the other sheets — a device-level cross-reference in the sense of EPLAN's cross-reference types (coil/contact and device references), generalised here to any symbol. A relay's coil and contacts keep their own coil ⇔ contact reference (see [Schematic editor](03-schematic-editor.md)) instead of this one, so the two never draw on top of each other
- **SVG export**: millimeter-true (1:1 viewBox), print-quality vector output; the SVG renderer is the single source of truth for printed appearance
- **PDF export**: vector conversion of the SVG with embedded fonts (CJK-capable), one page per sheet
- **Report set**: nine reports — from–to wire list, terminal chart, terminal connection diagram, bill of materials, cable list, cross-reference table, PLC I/O report, panel layout table, in-panel wiring diagram. See [Wire Management](05-wire-management.md) for the terminal chart and the wire list columns
- **Panel layout table**: one row per footprint on the panel sheets — item no. / designator / part no. / X / Y / rail. X and Y are the top-left corner of the drawn outline (the same coordinates the model stores) and rails are numbered from the top of the panel. The item number is the balloon number, and it is also the BOM's first column, so the layout table and the BOM always agree. Ribbon: Panel tab → Reports group → *Layout table*. Note that adding the item number changed the BOM's column set — the CSV is not compatible with the four-column version that came before it
- **BOM wire roll-up**: after the component rows, the BOM adds one row per wire part number, project-wide, with the total length of that part in the quantity column (metres, 2 decimals, e.g. `12.50 m`); wires whose part number cannot be resolved (see [Wire management](05-wire-management.md)) roll up together under a single `(unassigned)` row instead of being invented or dropped. A project with no wires gets no roll-up rows, so a parts-only BOM is unaffected. The roll-up adds rows, not columns. The wire rows write the quantity **with its unit** (`3.75 m`), unlike the component rows' plain counts, so a length is never mistaken for a count; a project whose unresolved wires carry no length gets no `(unassigned) 0.00 m` row
- **BOM catalog columns**: every BOM row looks its part number up in the parts database and adds six columns after the quantity — maker / name / unit price / currency / amount / purchase link (11 columns in all, so the CSV is **not** compatible with the earlier five-column version). Component rows, wire roll-up rows and accessory rows are all looked up by the text in the part-number column; the `(unassigned)` wire row and empty part numbers are not. A part number the database does not know keeps its row with the six columns empty. Amount = quantity × unit price; a wire roll-up row's quantity is in metres, so a wire's unit price is read as **per metre** (keep the parts database consistent with that). Prices are written to two decimals without trailing zeros. When at least one row has a price, the BOM ends with one `合計` (total) row per currency, whose name column says how many rows were left out for having no price (`単価未登録 N 行を除く`). The lookup happens wherever reports are written (the app, MCP and the Link API / `madake export`); if the parts database cannot be opened, the columns are simply left empty
- **In-panel wiring diagram**: for every footprint on the panel sheets, one row per schematic wire on each of its pins — panel / device / part no. / terminal / wire no. / destination / colour / sq (8 columns, CSV or framed pages; CLI `madake export panel-wiring`). Destinations are the other end's `designator:pin` or a net label. Nameplate part numbers appear in the BOM as one quantity row per part number
- **Cable list**: one row per multi-core cable — cable / part no. / cores / gauge sq / length m / devices at the From ends / devices at the To ends / cores used / spare cores / shield / sheet (11 columns, CSV or framed sheet; CLI `madake export cable-list`). The ends are read from the wires the cable's cores are assigned to; cores whose wire was deleted count as spare. In the BOM, cables appear per part number after the accessory rows, with the total length (`15.50 m`) when every cable of that part has a length, otherwise the number of cables; cables without a part number are left out
- **BOM terminal accessories**: after the wire roll-up, one row per accessory part number (end bracket / partition / end plate set on a terminal strip in the terminal editor), with the number used in the quantity column and the terminal strips that use it in the designator column. Accessories with no part number, or items the terminal check cannot read, add no row. A part number missing from the parts database is still listed as written (the editor warns about it). Limitation: accessory widths are **not** counted by the panel layout's rail fill or spacing checks
- **PLC I/O report**: one row per assigned point — module, address, signal name, target, wire number, comment. Address, signal name and comment come from the [I/O assignment table](03-schematic-editor.md); target and wire number are read out of the drawing every time the report runs, across **every sheet the module appears on** (the module is drawn on both the source sheet and the generated ladder page). Ribbon: Reports tab → PLC I/O group → *PLC I/O report*; CLI: `madake export plc-io <path>`
- **Reports as drawing sheets**: every report can be written as CSV *or* as framed A4-landscape pages — same JIS border and title block as the schematic, column headers repeated, long cells elided, and rows split across pages automatically. The terminal connection diagram is graphical, so it exists only in the drawing-sheet form
- **Combined PDF (drawing set)**: cover page (project name, sheet list, latest revision) → every schematic sheet → the selected reports, all in one PDF. Ribbon: Reports tab → Output group → *PDF book*; CLI: `madake export pdf-book <path> [--reports wire-list,terminal-chart,terminal-diagram,bom,xref,panel-placement] [--no-cover]`
- **Single report export**: `madake export bom|wire-list|terminal-chart|terminal-diagram|xref-table|plc-io|panel-placement|cable-list|panel-wiring <path> [--format csv|pdf] [--terminal <ref>]` (format defaults to the file extension)
