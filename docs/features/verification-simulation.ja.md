# 検証・シミュレーション

[English (canonical)](verification-simulation.md)

配線ミスを出図前に捕まえる。MadakeCADは図面からネットリストを抽出してERCを実行し、電気的な判定を経験則だけでなく**実回路ソルバ(ngspice)**の解に基づいて行う。

## 利用できる機能

### ネットリスト抽出
- 座標一致(2.5mmグリッド)・ジャンクション・同名ネットラベルから接続を導出。端子台は貫通接続
- 決定的なネット名(ラベル名、または N001… 連番)

### ERC(電気的ルールチェック)
- 未接続ピン(端子台は端子単位で判定。片側結線で接続扱い)
- 参照記号の未設定・重複(リレーのコイル+接点の共有は正しく許容)
- 宙ぶらりんのワイヤ端点(ジャンクション忘れの交差も検出)
- 1ネット上の異名ネットラベル(異電位短絡の典型)

### 電気検証(ngspiceバックエンド)
- 図面をSPICEデッキへ変換: ワイヤ=抵抗(ρ·L/A、途中接続で分割)、電源=電圧源、負荷=定格電流からの等価抵抗、スイッチ/接点/ヒューズ=mΩ橋
- チェック: 電源到達性・線径許容電流・電圧降下(電源電圧の3%)・ヒューズ定格。実解の電流・電圧で判定し「(シミュレーション値)」と明示
- **フォールバック**: ngspice未導入ならグラフ近似で動作し、Info診断で近似モードと表示
- 結果はドックパネルに表示。行クリックで該当エンティティを選択+ズーム。CLI(`madake verify`)・MCP(`run_verification`)でも実行可

### DC動作点シミュレーション
- ネット電圧(min〜max=配線降下の可視化)、部品の電流・電力
- **what-if開閉**: スイッチ/接点を開路指定(`--open SW1,K1`)して再解析
- リボンボタン+結果パネル、CLI `madake sim`、MCP `simulate_op`。ngspiceは`MADAKE_NGSPICE`→PATH→OS既定パスの順で探索

## 計画中

- 直列ヒューズの協調(選択性)(部品DBのSPICEモデル後)
- リレー接点数の検証(部品の実接点構成と使用数の突き合わせ)(M4)
- 過渡解析(部品DB由来の非線形/リアクタンスモデルが実運用されてから)
- KiCadエクスポート実装後の`kicad-cli sch erc`クロスチェック
