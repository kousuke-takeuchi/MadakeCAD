# 電線管理

[English (canonical)](05-wire-management.md)

産業配線図の要は電線データ(線色・線径・長さ・品番)。MadakeCADはこれらをワイヤの第一級属性として扱い、帳票と検証へ流し込む。

## 利用できる機能

- **ワイヤ属性**: 線色(日本の慣習を含む名前付きパレット)、線径sq(mm²)、長さ(m・任意)、電線品番、ネット名(任意)
- **配線注記(図面上)**: 各ワイヤが持つ線径・線色・電線長から `0.75sq 白 0.4m` の注記を作り、そのワイヤの最長セグメント上、**線番と反対側**(横線なら下、縦線なら右)に描く。欠けている属性はその場ごと省き、3つとも無いワイヤには注記が付かない。色名は英字の大小と前後の空白を無視して照合され、知っている色は印刷用の名前(`Red`も`red`も「赤」)、知らない色は入力のまま(ただし小文字にそろえて。`Turquoise`→`turquoise`、`#FF0000`→`#ff0000`)書かれる。凡例ブロックと電線品番表の引き当ても同じ名前を使うので、三者が食い違うことはない。画面では専用の表示クラスを持ち、SVG/PDFには**常に**出力される — 産業配線図では、これが電線を作るための情報そのものだから
- **電線品番マスタ**: 線色+sq→品番の引き当て。グローバル部品DBに保存(m単価・購入先URL付き)。図面ファイル側はスナップショットを持ち自己完結
- **電線品番の引き当て**: ワイヤに書かれた品番が最優先で、空のときだけ**線色+線径**でプロジェクトの電線品番表を引く(先に書いた行が勝ち、該当が無ければ空欄のまま)。電線リストとFrom-To帳票がこれに追従する。照合は前後の空白と英字の大小を無視し、さらに**英語名と日本語名を同じ色として扱う**ので、`青`と書いた表が`blue`のワイヤに効く。表はCSV(`線色,線径sq,電線品番[,備考]`・見出し任意)から**undo一発**の1コマンドで読み込める(`POST /api/v1/project/wire-parts/csv`、IPC `import_wire_parts_csv`も同じ)。プロパティパネルには引けた品番が「品番 (自動)」として出る
- **電線品番凡例ブロック**: 自動描画の表(回路図タブ→配線グループ→「電線品番凡例」)。シートの配線を線色+線径+電線品番(引き当ては上と同じ規則)の組ごとに1行へまとめ、そのシートでの使用長合計を添える。線色は同じシートの配線注記と同じ名前へそろえてからまとめるので、`red`と`赤`で記録された配線は2行に割れず1行になる。行は線色→線径→電線品番の順に並び、使用長はm単位・小数第2位で出す(部品表の電線集約行と同じ書式)。配線の無いシートでも列見出しは描く。中身は持たない — エンティティの詳細は[回路図エディタ](03-schematic-editor.ja.md)を参照
- **BOMの電線集約**: 部品表(BOM)には部品行の後ろに、電線品番ごとのプロジェクト全体の使用長合計を1行ずつ、品番が引けない配線は「(未割当)」の1行にまとめて付く — 詳細は[標準・出力](04-standards-output.ja.md)を参照
- **電気的意味**: 線径・長さは許容電流・電圧降下検証に使われる。端子台はネットリスト上で貫通接続
- **線番**: ネット単位の番号で、同じネットの全ワイヤに同じ値が入る。自動採番(「回路図」タブ→「配線」グループ→「線番採番」)は2方式 —「追い番」は既存の線番とネットラベルを保持して未採番のネットだけに振り、「振り直し」は自動採番済みの番号を全て振り直す(手入力の名前は常に保持)。採番順は上→下、同じ高さなら左→右で、シート指定なしなら図面全体で一意。ネットラベルとは番号が衝突しない。図面上は配線に沿って描画(横線は上、縦線は左)し、プロパティパネルでネット単位に個別編集できる。CLIからは `madake renumber [--sheet <ID>] [--mode append|renumber] [--start N]`
- **ハーネス境界**: まとめて製作・購入する電線束の範囲を囲む、名前(`W1`, `W2` …)と備考を持つ破線の囲み。**筐体・ケースの囲みは代わりに図形の矩形で描く**(「回路図」タブ→「図形」グループ): 筐体をハーネスで囲むと、中にあるだけの導線まで電線リスト・端子台チャートのハーネス列に筐体名で載ってしまう。所属は幾何学的に決まり、全ての点が囲みの内側にあるワイヤが所属する(入れ子は最も内側の囲みが優先)。「回路図」タブ→「配線」グループ→「ハーネス」ツールで矩形ドラッグして作り、プロパティパネルで名前・備考を編集できる(含む電線数も表示)
- **From-Toワイヤリスト**(CSV): シート・From・To・嵌合相手・備考・線番・線色・sq・長さ・品番・ハーネス。From/Toはワイヤ両端の接続先で、ピンは`参照記号:ピン番号`(`K1:A1`、`TB1:3`)、ネットラベルはラベル名、何にも接続していない端は空欄。両端のうち表記の辞書順で小さい方がFrom、未接続の端は常にTo。**ネットラベルに届いた端はネットを辿って解決する**(このワイヤ自身の反対端がピンならそれを除く): ネットに他のピンが**ちょうど1つ**あればそのデバイスの`参照記号:ピン番号`へ置き換わり、それ以外はラベル名のまま残って備考列に理由が立つ: 他のピンが複数あって1つに絞れなければ`multi`、ネットにデバイスのピンが1つも無く辿る先が無ければ`none`(両方当てはまる行は`multi`)。行は**ワイヤ1本につき1行**なので、同名ネットラベル対の両脇の2本のように同じデバイス対へ解決する2本のワイヤは、見た目が同じ2行になる(別々のワイヤで、線色・線径・長さはそれぞれ持つ)。**嵌合相手列とネットラベル解決は新設でTo列の直後に入るため、CSVは従来の9列とは非互換**(現在は11列) — 電線リストCSVを列位置で読んでいるスクリプトは直す必要がある(端子台チャートのLv列が自身の互換性を壊したのと同じ経緯)
- **嵌合コネクタ対**(G14): コネクタインスタンス(`connector_*`系統 — 動的`connector_{n}p`と静的`connector_plug`/`connector_socket`。端子台はこの用途ではコネクタに含まない)の`attrs["mates_with"] = "<参照記号>"`が対の片側を宣言する。両側に書くと対として完全に結び付く。ERC(嵌合相手は他シートも指せるのでプロジェクト全体で評価): 2つのコネクタの極数が食い違えば警告(`erc.mate_pole_mismatch`)、相手側が対応する指定を持たない片側宣言は参考情報(`erc.mate_one_sided`)、自己参照・不明な参照記号は警告(`erc.mate_unknown`)。電線リスト・From-To帳票の**嵌合相手**列には、デバイスへ解決した側の宣言値がFrom側→To側の順で入る(描いた向きで並びが変わらない)。図面上では、両方が同一シート上にあり50mm以内(50mmちょうどは含む)のときだけ、2つのインスタンスの外形の最短点どうしを結ぶ短い破線を自動で描く — それ以外は何も描かず、帳票だけが対を伝える。画面ではシンボルどうしを結ぶ線なので表示クラス「シンボル」に属し、シンボルを隠すと破線も消える(表示クラスは画面だけのもので、SVG・PDF出力には常に描かれる)。プロパティパネル(コネクタインスタンスには「嵌合相手」欄が出る)またはどのコマンド経路からでも編集できる。動的コネクタ系統への性別欄はまだ無い

- **端子台チャート**: 端子台1台につき1表、端子番号順に1端子=1行。端子・**Lv(段)**・内部側ターゲット・外部側ターゲット・線番・電線(色/sq/品番)・ハーネス・ジャンパを載せる。Lv列は多段端子台の端子の段記号(例 `1a`)が入り、単段の端子台では空欄のまま。何も結線されていない端子は「予備」として並ぶ。内部/外部は盤の慣行どおり、**左側ピンへの接続=内部側(盤内)、右側ピンへの接続=外部側(盤外)**(回転後の左右で判定)。CSVと図枠付き図面シートの両方で出力できる。**Lv列は新設で端子列の直後に入るため、CSVは従来の6列とは非互換**(端子台1台分は7列、プロジェクト全体版は8列)。列位置で読んでいるスクリプトは直す必要がある
- **端子接続図**: 同じデータのグラフィカル様式(EPLAN端子図様式)。端子ストリップを縦に並べ、**外部側=左・内部側=右**へ引出線を描き、同じハーネスの電線は角括弧でまとめてハーネス名を記す。予備端子は薄塗り、ジャンパは端子箱の縁の縦線で表す。多段端子台では端子ストリップが段の数だけの列に分かれ、列の上に段記号の見出しが付き、箱には段記号付きの完全な端子番号(`1a`,`1b`,…)が入るので、段は別々の端子の列として描かれる。1端子台=1ページ(端子15個ごとに自動分割)。PDFのみ
- **端子台エディタ**(「レポート」タブ→「端子台」グループ→「端子台エディタ」): 選んだ端子台のチャート行をグリッド表示し(チャートと同じ**Lv列**を持ち、多段端子台のときだけ出る)、ツールバーとフッタ(チャート・接続図の生成)を備える。ここでの編集はどれも端子台への`update_entity`コマンド1回なので、⌘Zで戻り、エディタ・チャート・端子接続図・図面のシンボルがすべて追従する
  - **サドルジャンパ**を隣接端子の間に掛ける。`attrs["jumpers"] = "1-2,3-4"`(対は端子の並び順)に保存される。多段端子台では段記号まで書く(`1a-1b`=同じ極の段またぎ、`1a-2a`=同じ段の隣の極)。段記号なしの指定や存在しない端子を指す指定は端子台チェックがエラーにする。図面のシンボル上では、2つの端子の印(丸)の隙間を埋める短いバーを普通の線の2倍以上の太さで引く——実物のサドルジャンパと同じ見え方
  - **並べ替え順**(ドロップダウン。`attrs["row_order"]`に保存。未設定・未知語は数値順): 数値順(既定)・英数順(端子番号を文字列として比較するので`10`が`2`より前に来る)・ページ順(その極の配線が読み順(上→下、左→右)に最初に現れる位置の順。未結線の極は最後)・外部ケーブル順(外部ハーネス名が最初に現れた極の順にまとめる)・ジャンパ順(ジャンパの掛かった極を先頭に)。**ページ順の比較は図枠のゾーン単位で、その端子台が載っているシートの中だけ**なので、配線が同じゾーンに入る極どうしは極番号順のまま並ぶ。どの並びを選んでも多段端子の各段は隣り合ったまま動き、チャートのCSV・図枠付き図面シート・端子接続図もエディタと同じ並びで出る
  - **自動採番**(ツールバー「採番」ポップオーバー: 開始番号・増分・接頭辞・結果ラベルのプレビュー・適用/キャンセル)。`attrs["terminal_numbers"]`(ピン順=端子台既定の番号と同じ並び)のラベルのカンマ区切りに保存され、未設定はシンボル既定(`1`,`2`,…、多段端子台なら`1a`,`1b`,…)を意味する。採番は各極の段記号を保ったまま極番号だけを変えるので、同じ極の全段は新しい番号を共有したままになる。ピン数と合わない個数・重複したラベル・空要素は図面を変えずに拒否される。**同じコマンドで`attrs["jumpers"]`と`attrs["pin_groups"]`の範囲も新しいラベルへ書き換わる**ので、ジャンパやピングループの範囲は採番後も実際に繋ぐ端子を指したままになる。ジャンパの隣接判定は表示ラベルの数値差ではなく端子台の生のピン配置で決まるので、増分を1より大きくしても物理的に隣り合う極どうしのジャンパは壊れない。上書きラベルは端子番号が出るあらゆる場所(エディタのグリッド・チャートCSV・図枠付きチャート・端子接続図・端子台チェック・回路図のシンボルそのもの)に反映される——SVG/PDF出力と画面のキャンバスは、生ピン番号→ラベルの同じ対応表から同じ置き換え後のラベルを描く。直接指定(`SetTerminalNumbers`。`numbers`に`null`で既定へ戻す)が採番の逆コマンドで、⌘Z一発で戻る。ラベルは空欄でも保存形の区切り記号「,」入りでも拒否され、前後の空白しか違わない2つは重複と数える。読めないジャンパ・ピングループの項目や、端子台に無い端子を指す項目は採番をそのまま通り抜けるので、図面検証はそれを指し続け、⌘Z一発で属性は1バイトも変わらず戻る。**ネットリスト・From-To は電気的なピン識別 (シンボル定義のピン番号) を使い、採番後の表示番号はチャート・接続図・図面に出る**
  - **図面へジャンプ**(ツールバーのボタン、または行のダブルクリック): エディタを閉じてからその端子台のシートへ切り替え、選択+ズームする。開き直すと同じ端子台・同じ行選択に戻る
  - **端子台チェック**: 予備端子と、存在しない端子を指すジャンパ。段の後からの編集・アクセサリはエディタ側の対応が必要で次フェーズ。段数(1〜3)は部品挿入時に一度だけ選び、`terminal_block_{n}p_{levels}l`として配置する。既定の1段はそのまま`terminal_block_{n}p`になるので、既存プロジェクトに影響はない
- **CLI**: `madake terminals [--sheet <ID>]`で端子台一覧(参照記号・極数・段数〈単段は空欄〉・型番・ジャンパ・シート・entity id)、`madake export terminal-chart|terminal-diagram <path> [--format csv|pdf] [--terminal <参照記号|ID>]`で書き出し

## 計画中

- **参照ベース採番**(M4): シート/ゾーンアドレス由来の線番(AutoCAD Electrical方式)
- **多芯ケーブル**(M4): 芯線をまとめるケーブルエンティティ、ケーブル一覧
- **FreeCADからの電線長書き戻し**(M5): 3D経路の実測長を`length_m`へ反映(出所フラグで手入力の誤上書きを防止)
