# 検証・シミュレーション

[English (canonical)](06-verification-simulation.md)

配線ミスを出図前に捕まえる。MadakeCADは図面からネットリストを抽出してERCを実行し、電気的な判定を経験則だけでなく**実回路ソルバ(ngspice)**の解に基づいて行う。

## 利用できる機能

### ネットリスト抽出
- 座標一致(2.5mmグリッド)・ジャンクション・同名ネットラベルから接続を導出。端子台は貫通接続
- 決定的なネット名(ラベル名、または N001… 連番)

### ERC(電気的ルールチェック)
- 未接続ピン(端子台は端子単位で判定。片側結線で接続扱い)
- 参照記号の未設定・重複(リレーのコイル+接点の共有は正しく許容)
- 宙ぶらりんのワイヤ端点(ジャンクション忘れの交差も検出)
- 1ネット上の異名ネットラベル(異電位短絡の典型)

### 電気検証(ngspiceバックエンド)
- 図面をSPICEデッキへ変換: ワイヤ=抵抗(ρ·L/A、途中接続で分割)、電源=電圧源、負荷=定格電流からの等価抵抗、スイッチ/接点/ヒューズ=mΩ橋
- チェック: 電源到達性・線径許容電流・電圧降下(電源電圧の3%)・ヒューズ定格。実解の電流・電圧で判定し「(シミュレーション値)」と明示
- **フォールバック**: ngspice未導入ならグラフ近似で動作し、Info診断で近似モードと表示
- 結果はドックパネルに表示。行クリックで該当エンティティを選択+ズーム。CLI(`madake verify`)・MCP(`run_verification`)でも実行可

### DC動作点シミュレーション
- ネット電圧(min〜max=配線降下の可視化)、部品の電流・電力
- **what-if開閉**: スイッチ/接点を開路指定(`--open SW1,K1`)して再解析
- **どのシンボルにも役割を付けられる**: シンボル定義の `sim`(`source` / `load` / `fuse` / `conductor` / `converter` / `none` と、役割が使うピン)でユーザーシンボルも解ける。値は置いた部品の属性: `voltage` / `r_int_ohm` / `i_max_a`(電源)、`current_a` / `v_min`(負荷。定電流)、`rating_a`(ヒューズ)、`v_out` / `eta` / `i_out_a` / `i_limit_a` / `v_in_min`(DC/DC変換器: 2つ目の電源電圧。入力は出力電力÷効率の電流を引く。電流制限と入力の低電圧停止も指定できる)、`pin_rating_a`(ピンごとの電流。コネクタなど)
- **条件**: 属性をその1回だけ置き換え(`--set M1.current_a=40`。モーターの拘束など)、ネットを接地へ短絡(`--short P24`)して事故電流を見る
- **定格超過**: ヒューズ・コネクタのピン・電源・変換器・負荷の端子電圧・電線の許容電流を解いた値と比べ、重い順に並べる(許容電流の表より太い電線は「判定していない」と情報で示す)。同梱の負荷はこれまでどおり抵抗のモデルで、定電流になるのは役割を付けた負荷だけ。絶縁された変換器の出力は負極を接地の基準にする
- リボンボタン+結果パネル(ネット電圧・部品電流・定格超過の列と件数。定格超過の行クリックで部品を選択+ズーム。条件バーに `参照記号.属性=値` と `短絡 ネット名` を入力)、CLI `madake sim`、MCP `simulate_op`。ngspiceは`MADAKE_NGSPICE`→PATH→OS既定パスの順で探索
