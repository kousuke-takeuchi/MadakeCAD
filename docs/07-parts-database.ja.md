# 部品データベース

[English (canonical)](07-parts-database.md)

全プロジェクトで共有するローカルファーストの部品マスタ(SQLite)。図面は型番で参照し、ファイル自体は自己完結を保つ。

## 利用できる機能

- **部品マスタ**: 型番(一意キー)・メーカ・名称・カテゴリ・既定シンボル(可変ピンID可)・定格電圧・定格電流・接点構成・PLCモジュール定義・購入先URL・データシートURL・価格/通貨・備考。3Dモデル参照/取付情報/SPICEモデルの予約列
- **接点構成**(`contact_config`、スキーマv3): リレー・電磁接触器が実際に持つ接点の数をデータシートどおりの書き方(`2NO+2NC`・`4NO`・`1CO`)で持つ。配置するとシンボルへ写るので、コイルの接点マップが未使用接点を`—`で並べられ、実装数を超えて使った図面をERCが指摘できる
- **PLCモジュール定義**(`plc_module`、スキーマv4): 点数・入出力の向き(`DI`/`DO`)・アドレスの接頭辞・メーカのアドレス体系(`mitsubishi`=8進 / `siemens`=バイト.ビット / `ab`=ワード/ビット)を持つ小さなJSON。これが入っている部品がPLCモジュールで、I/Oモジュールライブラリの選択肢に出て、点数に合ったピン数可変シンボル(`plc_di_16p`・`plc_do_8p`…)として配置され、[I/O割付表](03-schematic-editor.ja.md)のアドレス自動採番の元になる。`plc_module`が空欄の部品はふつうの部品
- **電線品番マスタ**: 線色+sq→電線品番、m単価
- **検索→配置**: 部品挿入ダイアログからDBを検索し、選択すると既定シンボルが「型番=value、定格電流・接点構成=検証用属性」付きで配置される
- **スキーマバージョン管理**+自動マイグレーション(現在v5)。初回にサンプル(ダミー型番)を投入し、3つのアドレス体系をひと通り含むPLCモジュール4種も入る。v5より前に作られたDBを開くとこのPLCサンプルが**足りないぶんだけ**追補される(同じ型番で自分が登録・編集した部品はそのまま)
- **どこからでも**: CLI(`madake parts`)、MCPツール(`search_parts`/`upsert_part`/`delete_part`)、REST(`/api/v1/parts`・`/api/v1/wire-parts`・`/api/v1/plc/modules`)。AIアシスタントが対話で登録・検索できる
- 既定の保存先: OSのアプリデータフォルダ(`MADAKE_PARTS_DB`で変更)
