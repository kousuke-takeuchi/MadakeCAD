# 多言語対応(i18n)— 横断仕様

**English (canonical): [i18n.md](i18n.md)**

ステータス: 2026-08-21承認。基盤はM6まで先送りせず今から導入し、以後の新規・変更UIは必ずメッセージカタログを経由する。**F3完了(2026-09-27)**: 6言語のカタログを同梱、残UIリテラルを移行済み、§6に翻訳者向け手順を記載。

## 1. 対応言語

| 区分 | 言語 | 備考 |
|---|---|---|
| 必須 | **英語(`en`、既定)**、**日本語(`ja`)** | 同時に出荷。キー一致をテストで強制。コアチームが保守 |
| コミュニティ | 中国語(`zh`)、スペイン語(`es`)、フランス語(`fr`)、ドイツ語(`de`) | 2026-09-27(F3)から同梱。初版は英語カタログからの翻訳。キー一致・プレースホルダ一致・非空を同じテストで強制し、欠落文字列は英語へフォールバック |

- **UIの既定言語は英語。** 日本語等は 設定 > 一般 > 言語 で明示的に選択する。選択はアプリ設定に保存され起動時に適用、変更は即時反映(再起動不要)。
- フォールバック: 選択ロケール → `en`。キー欠落時は英語文字列を出す(生キーを出さない)。

## 2. 対象と対象外

| 領域 | 対象? | 方法 |
|---|---|---|
| UIクローム(リボン・パネル・ダイアログ・ステータスバー・コマンドログ) | 対象 | vue-i18nカタログ(`src/locales/{en,ja,zh,es,fr,de}.json`) |
| 検証/ERC/シミュレーション診断 | 対象(F2) | コアは安定`code`+パラメータを返し、フロントでcode→ローカライズ文へ変換。コアの`message`は英語フォールバック |
| AIチャットの内容 | 対象外 | アシスタントがユーザーの言語で自然に応答する。MadakeCADが**組み立てるプロンプト**(整え指示・図面コンテキストタグ)は日本語固定のエージェント向け文で、UI文字列ではない |
| 図面内容(表題欄ラベル・改訂欄見出し・注記) | 対象外 — **図面言語はプロジェクト単位の規格設定**でUIロケールとは別 | JIS↔IEC様式テーマ(M4)。UI言語を変えても日本語図面の印刷結果は不変 |
| 帳票(BOM/電線リストCSVの見出し) | 対象(F2) | UIロケールでなくプロジェクトの図面言語に従う |
| CLI(`madake`)出力 | 後続 | 当面英語のみ。`--lang`フラグを予約 |
| ドキュメント | 対応済み | `*.md`(英語正本)+`*.ja.md`ルール |

## 3. アーキテクチャ

- **フロントエンド**: `vue-i18n`(Vue 3対応版。実装時にnpmレジストリで正確なバージョンを確認し、推測しない)。ロケールは`src/locales/`のJSON、キーは機能別名前空間: `ribbon.home.newProject`、`settings.agent.autoApprove`、`verify.rerun`。補間は名前付きパラメータ(`{count}`, `{name}`)、数依存文はvue-i18nの複数形機能を使う。
- **ロケール状態**: アプリ設定の`language`(`SUPPORTED_LOCALES`のタグ: `en`, `ja`, `zh`, `es`, `fr`, `de`)。欠落・未知は`en`。設定 > 一般 の言語ドロップダウンは`SUPPORTED_LOCALES`から生成されるので、カタログを足せば項目も増える。
- **Rustコア**: `madake-core`内ではローカライズしない。診断は安定`code`(テスト済み)+構造化パラメータを持ち、`message`は英語フォールバック文とする。コアのヘッドレス安全性とテスト容易性を保つ。
- **日付・数値**: `Intl` APIをアクティブロケールで使用。図面座標・品番はロケール整形しない。

## 4. ルール(即時適用)

1. 新規・変更するUI文字列は必ずカタログ経由 — コンポーネントへのユーザー可視リテラル直書き禁止(既存の日本語リテラルは触った画面から順次移行)
2. 全カタログは`en.json`とキー完全一致 — Vitestの仕様テスト(`src/i18n/i18n.test.ts`)が全ファイルを走査し、キーの欠落・余分、空文字列、英語と異なるプレースホルダ、複数形の数の違いで失敗する(テスト=仕様書ルール適用:「全UI文字列は同梱する全言語に存在する」)
3. キーは意味ベース(`settings.agent.redetect`)。英語文をキーにしない
4. コマンドラインへのログ(`ui.log`)もUI文字列 → カタログ対象
5. Pencilのモックはレビューしやすさ優先で日本語のまま。両言語の文言の正はカタログ

## 6. 翻訳者向け

翻訳者が触るのは`src/locales/`の言語ごとのJSONファイル1つだけ。ビルドツールやRustの知識は不要。

### 既存言語の改善

1. `src/locales/<locale>.json`(例: `de.json`)を、意味の正である`src/locales/en.json`と並べて開く。`ja.json`はレビュー済みのもう1つの参考。
2. 値だけを編集し、キーは変えない。キーは意味ベース(`settings.agent.redetect`)で全言語共通。
3. 名前付きプレースホルダ(`{count}`, `{path}`, `{sheet}` …)は英語と同じものをそのまま残す。実行時に置換されるので、名前を変えたり落としたりすると壊れる。
4. 複数形の区切り`|`は英語と同じ数の形を保つ(`{count} message | {count} messages`)。複数形の無い言語は同じ形を繰り返す。
5. 製品名・ツール名・拡張子・CLIコマンド・ショートカット(`Cmd+Z`)・モデルID・大文字のログ接頭辞(`SAVE  `, `AGENT   `)は変えない。`language.*`の言語名(自称)は全ファイル共通。
6. `npx vitest run src/i18n`を実行する。キーの欠落・空文字列・プレースホルダの変更・複数形の数の変更で失敗し、どのキーかを示す。次にUIで確認: 設定 > 一般 > 言語 で即時に切り替わる(再起動不要)。

### 言語の追加

1. `src/locales/en.json`を`src/locales/<tag>.json`(`pt`のような小文字のBCP 47主タグ)へコピーし、値を翻訳する。
2. `src/i18n/index.ts`の`SUPPORTED_LOCALES`と`messages`にタグを足し、**全カタログ**の`language.<tag>`にその言語の自称を足す(キー一致テストが要求する)。
3. `src/i18n/i18n.test.ts`の`CATALOGS`にカタログを登録し「ships … catalogs」の期待値を更新、本書§1の言語表と英語版も更新する。
4. [PRテンプレート](../../../.github/PULL_REQUEST_TEMPLATE.md)でプルリクエストを出す。CIで同じテストが走る。

### 意図的にカタログへ入れないもの

図面内容(表題欄・改訂欄見出し・注記)はUIでなくプロジェクトの図面言語に従う。AIへ送る整え指示・図面コンテキストのプロンプトは日本語のエージェント向け文。検証コードはフロントで文へ変換する(F2)。§2参照。
