# Internationalization (i18n) — cross-cutting spec

**日本語: [i18n.ja.md](i18n.ja.md)**

Status: approved 2026-08-21. Foundation lands early (not deferred to M6); every new or modified UI goes through the message catalog from now on. **F3 done 2026-09-27**: six catalogs ship, the remaining UI literals are migrated, and §6 documents how translators contribute.

## 1. Languages

| Tier | Languages | Notes |
|---|---|---|
| Required | **English (`en`, default)**, **Japanese (`ja`)** | Ship together; key parity enforced by test. Maintained by the core team |
| Community | Chinese (`zh`), Spanish (`es`), French (`fr`), German (`de`) | Shipped since 2026-09-27 (F3), initial translation from the English catalog. Key parity, placeholder parity and non-empty strings are enforced by the same test; a missing string falls back to English |

- **Default UI language is English.** Japanese (or any other) is an explicit choice in Settings > General > Language. The choice is stored in app settings and applied at startup; changing it takes effect immediately (no restart).
- Fallback chain: selected locale → `en`. A missing key must render the English string, never the raw key.

## 2. Scope and non-scope

| Area | Localized? | How |
|---|---|---|
| UI chrome (ribbon, panels, dialogs, status bar, command-line log) | Yes | vue-i18n message catalog (`src/locales/{en,ja,zh,es,fr,de}.json`) |
| Verification / ERC / simulation diagnostics | Yes (phase 2) | Core keeps emitting stable `code` + params; frontend maps code → localized template. Core `message` stays as English fallback |
| AI chat content | No | The assistant answers in the user's language naturally; not catalog material. The **prompts MadakeCAD composes** (tidy instructions, drawing-context tags) are Japanese-fixed agent text, not UI strings |
| Drawing content (title block labels, revision table headers, notes) | No — **drawing language is a per-project standards setting**, not the UI locale | JIS↔IEC sheet style theme (M4). A Japanese drawing must print identically regardless of UI language |
| Reports (BOM / wire list CSV headers) | Yes (phase 2) | Follows the project's drawing language, not the UI locale |
| CLI (`madake`) output | Later | English only for now; `--lang` flag reserved |
| Docs | Already bilingual | `*.md` (EN canonical) + `*.ja.md` rule |

## 3. Architecture

- **Frontend**: `vue-i18n` (Vue 3 build, verify exact version against the npm registry when implementing — do not guess). Locale files are flat JSON under `src/locales/`, keys namespaced by feature: `ribbon.home.newProject`, `settings.agent.autoApprove`, `verify.rerun`. Interpolation via named params (`{count}`, `{name}`); use vue-i18n pluralization for count-dependent strings.
- **Locale state**: `language` field in app settings (any tag in `SUPPORTED_LOCALES`: `en`, `ja`, `zh`, `es`, `fr`, `de`). Missing/unknown → `en`. The language dropdown in Settings > General is generated from `SUPPORTED_LOCALES`, so adding a catalog adds the menu entry.
- **Rust core**: no localization inside `madake-core`. Diagnostics carry `code` (stable, tested) + structured params; human `message` becomes the English fallback text. This keeps core headless-safe and testable.
- **Dates/numbers**: `Intl` APIs with the active locale; drawing coordinates and part numbers are never locale-formatted.

## 4. Rules (enforced from now)

1. New or modified UI strings must go through the catalog — no hardcoded user-visible literals in components (existing Japanese literals migrate incrementally; a screen is migrated fully when touched).
2. Every catalog must stay key-identical to `en.json` — a Vitest spec test (`src/i18n/i18n.test.ts`) walks all files and fails on a missing or extra key, an empty string, a placeholder that differs from English, or a different number of plural forms (tests-as-spec rule applies: it documents "every UI string exists in every shipped language").
3. Keys are semantic (`settings.agent.redetect`), never the English text itself.
4. Log lines sent to the command line (`ui.log`) are UI strings → catalog.
5. Design mockups (Pencil) stay Japanese-first for review convenience; the catalog is the source of truth for wording in both languages.

## 6. For translators

Everything a translator touches is one JSON file per language under `src/locales/`. No build tooling or Rust knowledge is needed.

### Improving an existing language

1. Open `src/locales/<locale>.json` (for example `de.json`) next to `src/locales/en.json`, which is the source of truth for meaning. `ja.json` is a second, fully reviewed reference.
2. Edit the value only, never the key. Keys are semantic (`settings.agent.redetect`) and shared by every language.
3. Keep every named placeholder exactly as in English: `{count}`, `{path}`, `{sheet}` … They are substituted at run time; renaming or dropping one breaks the string.
4. Keep the plural separator `|` with the same number of forms as English (`{count} message | {count} messages`). Languages without a plural distinction repeat the same form.
5. Leave product and tool names, file extensions, CLI commands, keyboard shortcuts (`Cmd+Z`), model IDs and the uppercase log prefixes (`SAVE  `, `AGENT   `) untouched. Endonyms under `language.*` are the same in every file.
6. Run `npx vitest run src/i18n` — it fails on a missing key, an empty string, a changed placeholder or a changed plural arity, and tells you which key. Then check the UI: Settings > General > Language switches at once, no restart.

### Adding a language

1. Copy `src/locales/en.json` to `src/locales/<tag>.json` (a lowercase BCP 47 primary tag such as `pt`) and translate the values.
2. Add the tag to `SUPPORTED_LOCALES` and to `messages` in `src/i18n/index.ts`, and add its endonym under `language.<tag>` in **every** catalog (the parity test insists on it).
3. Register the catalog in `src/i18n/i18n.test.ts` (`CATALOGS`) and update the "ships … catalogs" expectation, plus the Languages table in §1 of this document and its Japanese twin.
4. Open a pull request with the [PR template](../../../.github/PULL_REQUEST_TEMPLATE.md); the same test runs in CI.

### What is intentionally not in the catalog

Drawing content (title block, revision table headers, notes) follows the project's drawing language, not the UI; the tidy and drawing-context prompts sent to the AI are Japanese agent text; verification codes are mapped to messages by the frontend (F2). See §2.
