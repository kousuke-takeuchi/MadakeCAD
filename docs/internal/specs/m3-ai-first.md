## 1. A1持ち越し負債の解消(基盤の信頼性)

A1プラン「既知の制限」(`docs/superpowers/plans/2026-08-20-phaseA1-ai-chat-and-cli.md`)の3件:

- **ターン安定ID**: `ChatMessage`にturn_id(UUID)を追加し、`undo_turn(turn_id)`へ移行(chat.jsonのformat_version++)。message_index指定を廃止
- **編集origin**: Engineの履歴エントリに`origin: user | agent | mcp`を追加。ターン巻き戻しがユーザー編集を巻き込まない
- **キャンセルseq**: broadcastイベントにターンseqを導入し、キャンセル後の遅延イベント誤着弾を排除

受け入れ基準: ターン中にユーザーが手編集しても「元に戻す」はエージェント編集だけを戻す。過去ターンの巻き戻しが安定IDで安全に効く。
→ **達成(フェーズ1)**。巻き戻しは`Engine::revert_range`がターンのundo深さ区間からagent由来エントリだけを逆適用し、衝突時は部分適用せず`RevertConflict`。

## 2. 規格知識の内蔵(エージェントの作図品質)

### 仕様
- **ドメインシステムプロンプト**: エージェント実行時に規格・慣習の知識を注入する(JIS C 0617記号の使い分け、参照記号接頭辞規則、線色/sq慣習、図枠・線番・ハーネスの決まり)。`madake-agent`の`--append-system-prompt`に組み込み、設定でカスタム追記可
- **図面コンテキスト自動供給**: ターン開始時に現在図面の要約(シート・ネット・検証結果)を自動添付(既存drawingContextの拡張)。**検証ループ**: エージェントが編集後に`run_verification`を自走し、Error診断が残る場合は自動修正を試みる(上限N回)
- **テンプレート**: 「24V制御回路の雛形」「モータ起動回路」等の開始テンプレート(Command列 or .mdkproj断片)をアプリ同梱し、チャット/新規作成から選択

### 2b. ナレッジサービス(EPLAN Copilot Knowledge Service相当)

- チャットが「操作の仕方」「規格の決まり」への質問に、**このアプリの実手順**(リボン位置・ダイアログ名)と**規格根拠**(IEC/ISO/JIS該当箇所)つきで回答できるようにする。ドキュメント(docs/03〜11)と規格ノートをエージェントの参照コンテキストとして同梱し、回答には出典(ドキュメント名)を添える
- 未対応機能への質問には「M4で対応予定」等のロードマップ回答を返す(feature-inventoryを参照させる)

### 2c. AI設計レビューと検証計画(Flux相当)

- **設計レビュー**: 「レビューして」でエージェントがERC/電気検証の結果に加え、決定的検証では拾えない観点(参照記号の体系・線色/sq慣習・ラベル命名・図面の見やすさ・規格チェックリスト)をレビューし、指摘一覧(重要度つき)を返す。修正はユーザー承認後にCommandで実行
- **検証計画**: 「この図面の動作確認手順を作って」で、機能確認の手順表(操作→期待結果)を生成し、注記または帳票として図面に残せる

### 2d. 部品選定支援

- 部品DB+定格を使った選定・**比較表**(最大10件、定格・価格・購入先の差分)・代替部品提案。配置済み部品の「これと互換の2極版は?」等に回答し、承認で置換コマンドを実行

### デザイン対象
- 新規作成時のテンプレート選択UI
- チャットの「検証ループ中」表示(ツールチップの拡張)
- レビュー指摘一覧の表示(検証パネルへのAIレビュー行追加 or チャット内カード)

## 3. 自動反復(整えループ。A2) — フェーズ2

デザイン済みポップアップ(`MadakeCAD.pen`「AIチャット - ポップアップ集」)の実装。

- **配置整理 / 配線整理 / ラベル整頓**: 選択範囲(または全体)に対しエージェントが「グリッド整列・交差削減・ラベル重なり解消」を反復実行。各反復はターンとして履歴に乗り、まとめてundo可
- 反復の停止条件: 改善スコア(交差数・重なり数)が収束 or 上限回数
- コア支援: 交差数・ラベル重なり検出のヘルパをmadake-coreに追加(エージェントが目標値として使う)

受け入れ基準: 乱雑に配置した回路が「配置整理」で2.5mmグリッド・重なりなしに収束し、undo一発で戻る。

## 4. 並列エージェント(A2) — フェーズ2

- 複数会話の同時実行(作業分担)・同一指示の比較案生成。デザイン済みポップアップ準拠
- 編集競合はCommandエンジンの直列実行で自然に整合(revision順)。会話ごとに編集オーバーレイの色を変える
- 同一会話の中は従来どおり1ターンずつ(実行中の会話への追加送信は拒否)。送信ガードは**開いている会話**にだけ効き、別の会話へ切り替えれば同時に頼める
- **ターン単位の巻き戻しの粒度**(フェーズ2実装で確定): 編集の由来は「エージェントか否か」までしか分からない(MCPの入口が会話を名乗らない)。そのため同時に走った2ターンの編集が混ざった区間を戻すと、**両方のターンの編集がまとめて戻る**。巻き込まれたターンは巻き戻し済みとして扱い、「適用済み」表示のまま空振りする「元に戻す」を残さない。会話ごとに選り分けて戻すには、ターンごとのMCP識別(接続単位のトークン等)が要る — 必要になった時点で設計する
- 同じ理由で、図面patch由来の編集ハイライトは会話を特定できない。**2つ以上の会話が同時に走っている間**のpatch由来の領域だけは既定色で描く(ツール呼び出し由来の領域は会話色で描ける)

## 5. マルチプロバイダ(A3) — フェーズ2・3で完了

| 経路 | 実装 | 認証 | 状態 |
|---|---|---|---|
| Claude Code CLI(既定) | `ClaudeCliBackend` | CLI自身のサインイン。保存物なし | ✅ A1から通し確認済み |
| Anthropic API | `AnthropicApiBackend`(Messages API・SSE) | キーチェーン`anthropic_api_key` | 🔶 実キー通しはユーザー確認事項 |
| GitHub Copilot CLI | `CopilotCliBackend`(`copilot -p … --output-format json`) | CLI自身のGitHubサインイン。**トークンは保存しない** | 🔶 `/login`後の通しはユーザー確認事項 |
| OpenAI互換 | `OpenAiCompatBackend`(`/chat/completions`・SSE) | キーチェーン`openai_compat_api_key` | 🔶 モック+Ollamaで実証 |
| Ollama(ローカル) | 同上(ローカルURLプリセット) | 不要(ローカルURLはAuthorizationごと省略) | ✅ 実機で作図1ターン通し確認済み |

- **キーはOSキーチェーン保存**(設定ファイルには項目自体を作らない)。ツールは全経路で共通の`ToolBridge`(内蔵MCPサーバーをプロセス内で呼ぶ)、ツール往復は上限16
- 設定画面: プロバイダ選択+経路ごとの詳細欄(パス / URL / モデル / 伏せ字キーの保存・削除)、接続テスト、検出バッジ

受け入れ基準: claude CLI無しの環境でも、APIキー設定のみでチャット作図が動く。キーがファイルに平文で残らない。
→ **達成**。Ollama(キー不要のローカルURL)経路で、`claude` CLIを使わずに作図1ターンを通した。平文非保存はテストで固定。
