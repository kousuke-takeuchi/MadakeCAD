## 1. 機密スキャン

### 1.1 手法

作業ツリーの追跡ファイル全件、および `git rev-list --objects --all` で列挙した**過去に一度でもコミットされた全blob**(テキスト・バイナリとも)、さらに全コミットメッセージを、以下のカテゴリの正規表現でスキャンした。差分 (`git log -p`) ではなくblob単位で走査しているため、途中で削除された内容も検出対象に入る。

| カテゴリID | 対象 |
|---|---|
| CUST | 参考図面に登場する顧客企業名(和文表記・ラテン表記の両方) |
| REFFILE | 参考図面PDFのファイル名およびその識別子部分 |
| DOCNUM | 顧客固有の図番・電線品番の採番体系 |
| CONN_PN | 参考図面に登場するコネクタ実型番の系列 |
| RELAY_PN | 参考図面に登場するリレー実型番 |
| NETNAME | 参考図面のネットラベル命名形式 |

### 1.3 要対応: `MadakeCAD.pen` に残る顧客由来の識別子

REFFILEとDOCNUMの検出は**すべて `MadakeCAD.pen`(Pencilデザインファイル、リポジトリ直下・git追跡下)に集中**している。他のいかなるファイルにも存在しない。

- 内容の性質: 図枠モックアップのプレースホルダ文字列と、AIチャットのサンプル会話文に、参考図面から採った実在のプロジェクト名・電線品番がそのまま入っている
- 現作業ツリー: DOCNUM 6件 + REFFILE 1件
- 履歴: `MadakeCAD.pen` に触れた**16コミット中14コミット**の版に同種の識別子が含まれる(短縮ハッシュ: `6c32f35`, `bc23cbb`, `25926f4`, `1674684`, `6c86e4b`, `d7fdba1`, `5cf93bd`, `226aa69`, `7fcc779`, `fa70ca8`, `1c62d7f`, `f9f7cc7`, `497073c`, `d2be39c`)
- **注意**: `MadakeCAD.pen` は暗号化されているとされるが、実体はUTF-8テキストであり、これらの文字列は平文で `grep` 可能な状態にある
- **さらに重要**: この14コミットは**すべて `origin/master`(GitHubリモート `kousuke-takeuchi/MadakeCAD`)にpush済み**である。当該リポジトリが現在privateであれば実害はないが、**そのリポジトリの可視性をpublicに切り替える形での公開は不可**

対応の選択肢(いずれも**ユーザー判断・ユーザー実行**):

1. **(推奨)** `MadakeCAD.pen` のプレースホルダ文字列を架空の値へ差し替える(Pen.app + pencil MCPで編集)。あわせて公開は新規リポジトリへのスカッシュエクスポートで行う(§1.5)
2. `MadakeCAD.pen` を公開対象から外す(`.gitignore` へ追加し、デザインはローカル資産とする)。ただしdesign-firstの開発フローを外部コントリビュータへ開く方針とは矛盾する
3. 現リポジトリの履歴を書き換える(`git filter-repo` 等)。**本監査では実行していない。**push済みのため協調者・フォーク・GitHubのdangling objectに残り、確実な消去にならない点に注意

### 1.4 低リスク判定の根拠(RELAY_PN / NETNAME)

- **RELAY_PN**: 検出されたリレー型番は、国内外の複数ベンダから一般に市販されている汎用8ピンリレーの型式であり、顧客固有の情報ではない。用途はすべて `reports.rs` / `io.rs` / `model.rs` などのテストフィクスチャ、デモプロジェクト、部品DBのサンプル行、プロパティパネルのプレースホルダ。回路例に汎用部品の型番を書くのと同等で、開示にはあたらない
- **NETNAME**: 「電圧-用途-連番」という命名規則の一例で、`standards.md` では命名規約の説明例として明示的に使われている。産業図面で広く見られる形式であり、顧客を特定しない。用途はすべてテストのネット名と仕様書の例示

いずれも公開の障害にはならないと判断する。最大限の慎重を期す場合は、デモ・テストフィクスチャの値を完全に架空のものへ置換できるが、必須ではない。

### 1.5 公開方法の判定と推奨

| 選択肢 | 機密リスク | 履歴の価値 | 判定 |
|---|---|---|---|
| A. 現リポジトリをそのままpublic化 | **高**。§1.3の14コミットが即座に公開される。過去の除去コミット `1ff7a8f` の親コミットも残る | 256コミットの開発経緯がそのまま残る | ❌ 非推奨 |
| B. 現リポジトリの履歴を書き換えてpublic化 | 中。push済み履歴の完全な消去は保証できない(フォーク・キャッシュ・dangling object) | 大部分は保てる | ⚠️ 次善 |
| C. **公開用の新規リポジトリへスカッシュエクスポート** | **低**。公開されるのは畳んだ後のツリーのみで、過去のblobは一切含まれない | 失われる。ただし `docs/superpowers/plans/` と `docs/internal/` が設計判断・実装経緯を文書として保存しており、実質的な代替になる | ✅ **推奨** |

**推奨: C(新規リポジトリへのスカッシュエクスポート)。** 現リポジトリは開発用のprivateリポジトリとして継続し、公開用は別リポジトリとする。この方式なら §1.3 の対応も「エクスポート直前に `MadakeCAD.pen` を差し替える」だけで完結し、履歴の追跡が不要になる。

補足: `MadakeCAD.pen` の差し替えを先に済ませるなら、節目コミットのみを再構成する中間案(数十コミット規模の再構築)も取れる。ただし手間に見合う価値があるかは要判断。

具体的な手順は M6 Task 5 の `docs/internal/release-runbook.md` に記載する(**実行はユーザー**)。

### 2.2 ACADE / EPLAN 由来素材

- リポジトリ全体で `EPLAN` / `AutoCAD` / `Autodesk` / `SOLIDWORKS` / `ACADE` を含む行は**97行**。内訳を確認した結果、**すべて比較・ベンチマーク・慣習の説明を目的とした指示的言及(nominative use)**であり、次のいずれにも該当しない:
  - 当該製品のアイコン・画像・スクリーンショットの同梱: **0件**(履歴上のバイナリblob63件はすべて自作アイコン/ロゴ、§1.2)

  - 特定画面のデッドコピー: デザインは `MadakeCAD.pen` 上で独自に構成しており、既存製品の画面レイアウトを写した成果物は無い
- 機能概念を参考にした独自実装はOSSの確立した慣行であり、問題は無いと判断する
- 対応として **README(EN/JA)に商標notice節を追加**した(各社商標の帰属明記・非提携の明示・素材非同梱の明示)
