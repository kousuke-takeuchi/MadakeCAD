# エージェント作図の比較: MCP 経由のスクリプトとアプリ内エージェント

日付: 2026-10-22 · 英語版 (正): [2026-10-22-agent-drawing-comparison.md](2026-10-22-agent-drawing-comparison.md)

## 条件

同じ図面を 2 回作った。ホワイトボードの写真と BOM の表から作る、AOGU CoCo の配線図である。A3 で 3 枚 (給電、USB と制御、音声) ある。USB のケーブルは単線で描く。電源、音声、LTE、I2C、UART は複線で描く。コネクタはプラグとソケットの組で描く。

1. **MCP 経由のスクリプト。** Python の補助スクリプト (手順書 `drawing-madakecad-wiring` の `mdk_draw.py`) が MCP のツールを呼ぶ。このスクリプトは、ブロックとピンの位置関係を知っている。各シートを描くスクリプトは、もう書いてあった。
2. **アプリ内エージェント。** 提供元は Claude Code CLI 2.1.285。同じ指示を、写真と BOM を添付して渡した。

## 結果

| | MCP 経由のスクリプト | アプリ内エージェント |
|---|---|---|
| 時間 | 4.6 秒 | 約 40 分 |
| ツール呼び出し | なし | 44 回 (Grep 12、Read 8、execute_commands 11、run_verification 4、get_tidy_metrics 4、その他 5)。エラー 0 |
| 検証 | 意図して未接続にしたピンだけ | エラー 0。警告 2 (スピーカーの「電源が届いていない」、誤検知) |
| 整頓指標 | なし | すべて 0 |

エージェントは、次のことをうまくできた。

- シートの分け方、BOM の番号、単線と複線の決まり、筐体の囲み、部品表、表題欄を守った。
- 多極コネクタの記号と、かみ合わせを示す点線を使った。
- 報告の前に、整頓指標を自分で確かめた。
- 資料どうしの食い違い (アンプの型番の違いなど) を報告した。

## 見つかった問題 (影響が大きい順)

1. **エージェントがピン位置を手で計算する。** ブロックの丸めとピンのずれを自分で計算した。計算の間、約 10 分ツールを呼ばなかった。40 分の大半はこれによる。
2. **手順書の補助スクリプトがアプリ内で動かない。** エージェントは手順書を読んだ。そのうえで、シェルが禁止されているのでスクリプトを動かせない、と言った。
3. **参考資料が見つからなかった。** 以前の複線図の SVG と、再起動基板の設計メモが見つからなかった。そのため、Pi の GPIO のピン番号が無い。LTE 基板の J1 が、EN# と GND の 2 本ではなく 1 本になった。
4. **指示と違う判断を、質問せずにした。** 指示は「ホワイトボードどおり」だったが、Pi への給電を、ハブの OTG 端子から Pi のデータ用端子へ描いた。
5. **最後の返答で、途中の文章がつながる。** ツール呼び出しの間の文章が、改行なしにつながる。
6. **Link API から、ターンが応答中かどうか分からない。** `/agent/conversations` に「応答中」の状態が無い。
7. **電源の到達チェックが誤検知する。** バッテリーやアンプのようなブロックが、電源として扱われない。
8. **エージェントが保存しなかった。** 保存先を聞いて止まった。

## ピン操作ツールでの再測定 (2026-10-22)

同じ指示と添付ファイルで、`feature/mcp-pin-tools` の開発版を使った (まとめて送る形あり、かみ合わせの間隔はまだ 3.5mm、プラグにも参照記号を付けられる状態)。

| | 1 回目 | 再測定 |
|---|---|---|
| 時間 | 約 40 分 | 22.5 分 (1351 秒) |
| ツール呼び出し | 44 回 | 62 回 |
| ピン操作ツール | なし | `place_mate` 3 回 (70 組)、`connect_pins` 7 回 (約 110 本)、`get_pins` 2 回 |
| 検証 | エラー 0 | エラー 0、未接続ピン 0 |

- `execute_commands` も 15 回使った。部品、文字、図形、配線 34 本に使っていた。
- `connect_pins` が 3 回失敗した。5200 バイトの入力で、エージェントが壊れた JSON を送ったため。エージェントはリストを分けて続けた。
- 同じ日の前の試行では、エージェントは 1 本ずつのツールを一度も呼ばなかった。代わりに、最大 181 件の `execute_commands` をまとめて送っていた。そのため `connections[]` と `mates[]` を足した。

残った問題 (影響が大きい順):

1. **エージェントがプラグの参照記号を空にした (警告 102 件)。** 両方に同じ記号を付けると、文字が二重に重なって描かれる。組の片方は記号を表示しない仕組みが必要。
2. **整頓指標が、組ごとに重なり 1 件とグリッド外 2 件を数えた。** 同じブランチで直した: かみ合わせの間隔を 5mm にした。
3. **エージェントがシートを目で見られない。** シェルが無いので PNG に描き出せず、文字の重なりは数値だけで確かめた、と書いていた。
4. **整頓指標が、どこが重なっているかを返さない。** エージェントは文字の重なり 5 件と 21 件の場所を見つけられなかった。
5. **以前からある問題:** エージェントが Grep でソースを読む。返答で途中の文章がつながる。
6. **新しいバグ: アプリを再起動しても CLI のプロセスが残る。** 開発版アプリが再起動したとき、中断した試行のエージェント CLI が動き続けた。新しいアプリの MCP につなぎ直し、次の試行の図面に 334 件の編集を書き込んだ。その編集は、次の会話のターンとして記録された。

## 後続の変更を全部入れた試行 (2026-10-23)

同じ指示と添付ファイルで、#8〜#12 を手元でまとめ、プラグの参照記号を印字しない変更 (この変更) も入れたビルドを使った。

| | 1 回目 | ピン操作ツール (#8) | 後続を全部入れた状態 |
|---|---|---|---|
| 時間 | 約 40 分 | 22.5 分 | 29 分 |
| 警告 | 2 | 104 | 2 (どちらも既知の電源到達チェックの誤検知) |
| 文字の重なり (シートごと) | 測っていない | 5 / 21 / 0 | 0 / 0 / 0 |
| シンボルの重なり、グリッド外 | なし | 全シートで残った | 0 |
| シート画像を見た回数 | 0 | 0 | 11 (うち 7 回は一部を拡大) |
| 未接続ピン | 0 | 0 | 0 |

- 増えた時間は、シートを画像で見て、見つけたものを直すのに使われた。残った整頓の問題は、配置上避けられない交差 1 か所だけ。
- 7 回のツール呼び出しが失敗した。エージェントが配線ごとの「黒」の注記を消そうとして `color: ""` を送り、空の文字列が途中で抜けた (`"color": }`) ため。別の変更で直した: 線径も長さも無い黒の配線には注記を付けない (#13)。
- #9 もアプリで確かめた。強制的に再起動したあと、前の CLI の次の書き込みは「前の起動」のメッセージで断られ、CLI は止まり、新しい図面は 7 分間白紙のままだった。
