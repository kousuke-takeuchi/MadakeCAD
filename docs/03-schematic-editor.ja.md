# 回路図エディタ

[English (canonical)](03-schematic-editor.md)

産業用電気図面のための専用エディタ。AutoCAD Electrical級ツールの慣習(リボンUI・ダークな作図領域・mm座標・2.5mmグリッド規律)に沿って設計。

## 利用できる機能

- **キャンバス**: パン(中ボタン/Space)、ホイールズーム、グリッド表示、用紙枠、クロスヘア。座標はmm・左上原点
- **シンボル**: JIS C 0617 / IEC 60617系の同梱51種 — 電源・変換・接地(交流電源・変圧器・整流器・保護接地/フレーム接地)、保護(ヒューズ・配線用遮断器1/2/3極・断路器)、操作スイッチ(押しボタンa/b接点・非常停止・切替/3位置スイッチ・リミットスイッチ)、リレー・電磁接触器(コイル・a/b/c接点・3極主接点)、半導体、受動部品、負荷(三相/単相/直流電動機・ランプ・ベル、および絵記号の**拡声器**・**ブザー**・**サイレン**・**送風機**――確立したJIS C 0617 / IEC 60617の図記号のみ、それぞれ標準の項目を出典に明記する――拡声器と送風機はIEC 60617の項目番号、ブザーとサイレンはJIS C 0617-8:2011 第10節(対応するIECの識別番号は未確認)。創作の絵は描かない)、計測器(電圧計・電流計・変流器)、接続器 — に加えて**ピン数可変シンボル** `connector_{n}p` / `terminal_block_{n}p`(1〜50極・5mmピッチ)、および下記の**汎用ブロック**(`block`)。`terminal_block_{n}p_{levels}l`(1〜3段、例 `terminal_block_8p_2l`)は段ごとに1列の端子が横に並ぶ(極が行なので`1a`と`1b`は同じ高さ)。ピン番号には段記号が付き(`1a`,`1b`,…)、段どうしは互いに短絡しない。全接続点は2.5mmグリッド上で、列と列の間には配線が通る隙間がある。端子台チャート・端子接続図・BOMには常に1台のデバイスとして載る。全記号がピンの接続方向・属性スロット(参照記号・型番・説明・定格)・日英の検索キーワードを持ち、多極機器は極ごとの端子番号(1/2・3/4・5/6)で極ごとに導通する。端子台は貫通端子(同一端子の左右は内部接続)としてモデル化。端子台のジャンパ(`attrs["jumpers"]`)は端子台チャート・端子接続図に加えて、図面上のシンボル自体にも、ジャンパされた2端子の印の隙間を埋める太いショートバーとして描かれる。多段端子台では段記号まで書く(`1a-1b`=同じ極の段またぎ、`1a-2a`=同じ段の隣の極)。段記号なしの数字だけの指定は推測せずに不正として扱う
- **ピングループ括弧**: `block`・`terminal_block_*`・`connector_*`のインスタンスは`attrs["pin_groups"]`(`"1-4:電源,5-8:信号"`のようなカンマ区切りの「範囲:名前」)を持てる。範囲の最初のピンから最後のピンまでピン列の脇に角括弧を描き、名前は縦書きの近似として4文字ごとに改行してその脇に積む。範囲は**チャート順**(シンボル定義に並んだ順。多段端子台の`1a-4a`は1段の中で連続する)でピンを指し、括弧の向きはピン自身の向きに従うので、回転・ミラーへ自動で追従する。括弧はピンの足先より外、名前はさらにその外に置き、参照記号・型番・機能ラベルのほうが避けて配置される。多段端子台では括弧をその段の列の外側の縁に掛ける。範囲の重なり・存在しないピン・読めない項目は、対象のデバイスと悪い項目名を添えたERC診断として報告され、その項目だけ描かれない(図面の他の部分には影響しない)。**ピン番号そのものに「-」が入っている端子はグループに指定できない**(ブロックのピン番号は自由文字列で、「-」は範囲の区切り記号のため)。その項目はその理由を添えた診断として拒否される。**多段端子台の段をまたぐ範囲**(例`4a-1b`)も同様に括弧を描けない(段ごとにその列の外側へ括弧を掛けるので、1本の棒では両方を囲めない)。黙って何も描かれるのではなく、同じ診断として拒否される。実機ブロック表示のコイルに付けたピングループも同様に報告される(実機ブロックには括弧を掛けるピン列が無いため)
- **配置**: 挿入ダイアログ(検索・カテゴリ別グリッド・極数ステッパー・部品DBセクション=配置時に型番と定格電流を自動設定)。ゴーストプレビュー、`R`で回転、参照記号の自動採番(F1, K2, TB1, …)
- **名前付きピンの機器ブロック**: コントローラ・ドライブ・アンプのような「箱に名前付きピンが並ぶ機器」は、部品挿入の**ブロック(汎用)**から**ピン表**(辺ごとに1行=ピン番号+ピン名)を埋めるとその場でシンボルが生成される。ピン名は外形の内側、ピン番号は外側のリード上に描かれ、ピンは2.5mmグリッド上の5mmピッチ、外形寸法は自動または指定。形はインスタンスが持つので(`attrs.block_pins` / `attrs.block_size`)、ライブラリに登録しなくてよく、同じシートのブロック同士が別々の形でよい。ネットリスト・ERC・BOM・端子接続表・両レンダラが同じ生成定義を使い、ピン番号の重複や空はコマンドの時点で拒否される。ピン表はプロパティパネルの「ピン表を編集…」からも開け、確定は**undo一発**
- **配線**: 直交ポリラインツール(グリッドスナップ+ピンスナップ菱形マーカー)、ジャンクション、ネットラベル、注記テキスト
- **配線注記**: 各ワイヤが持つ線径・線色・電線長から `0.75sq 白 0.4m` の注記を、最長セグメント上の線番と反対側へ自動で描く → [電線管理](05-wire-management.ja.md)
- **方向付きネットラベル**: ネットラベルは左向き/右向きの五角形の旗として描ける(プロパティパネル「タグ形状」)。信号がそこから出るのか入るのかが一目で分かる。枠は文字幅に追従し、タグ指定の無いラベルは従来どおりの見た目のまま
- **注記の装飾**: 自由注記は基準位置(左/中央/右揃え)・**色トークン**(`default` / `accent` / `warning` / `success` / `muted`)・太字を持つ。色は意味であって実際の色ではなく(画面と紙でそれぞれ読みやすい色に置き換わる)、生の色コードは拒否される。シンボルには第3のテキスト欄=**機能ラベル**(例「非常停止ボタン」)があり、シンボル定義の`FUNCTION`スロット、無ければ外形の下に描かれる
- **注記の引き出し線**: 自由注記は同じシート上の任意のエンティティを指す引き出し先(`leader_to`)を持てる。注記自身の外接矩形のうち対象にいちばん近い辺の中点から、対象の外接矩形上のいちばん近い点まで直線を引き、対象側の端には配線の分岐点と同じ大きさの丸印を描く――注記か対象のどちらを動かしても、描くたびに求め直すので常に追従する。存在しないエンティティや注記自身を指す`leader_to`は拒否される。対象を後から消した場合、注記は引き出し線を描かなくなり、検証が行き先の無い引き出し先として報告する。プロパティパネルにはまだ操作欄が無い(パネルにエンティティを選ぶ部品が無いため)。コマンド(注記への`UpdateEntity`)・CLIの`exec`・MCPツールから設定する
- **編集**: クリック/Shift/矩形選択、ドラッグ移動(スナップ)、削除、完全なundo/redo(⌘Z/⇧⌘Z)— UI・AI・CLI・APIどの入口の編集も単一の履歴を共有
- **シート**: 複数シート(タブ切替・追加)。作成後にシートの用紙サイズ・向きを変えられる(「用紙サイズ」ダイアログ、「回路図」タブ→「編集」グループ、または`set_sheet_paper`コマンド) — 描いたものは動かず失われず、新しい用紙の外に出たエンティティはERC警告として報告される
- **プロジェクト情報**: プロジェクト名・番号と、全シートの表題欄(会社名・図番・表題)を1コマンドでまとめて設定する(「プロジェクト情報」ダイアログ、「回路図」タブ→「編集」グループ、または`set_project_meta`) — 表題欄バインドへの反映は[標準出力](04-standards-output.ja.md)を参照
- **嵌合コネクタ対**: コネクタインスタンス(`connector_*`系統)は参照記号で嵌合相手を宣言できる(プロパティパネル→「嵌合相手」、または`attrs["mates_with"]`)。対はERCでチェックされ、電線リスト・From-To帳票に載り、近くにあれば図面上に短い破線が描かれる — 詳細は[配線管理](05-wire-management.ja.md)
- **線番**: ネット単位の自動採番(追い番/振り直し・開始番号・シート指定/プロジェクト全体)、プロパティパネルでのネット単位編集、専用の表示クラス
- **ハーネス境界**: まとめて製作・購入する電線束の範囲を囲む、名前付きの破線囲み。完全に内包された電線は電線リストのハーネス列に載る。筐体・ケースの囲みは代わりに**図形**の矩形で描く(帳票に影響しない)
- **図形**: 純粋な作図要素としての矩形・線・円・折れ線。色トークン・線幅0.1〜2.0mm・任意の薄い塗り・破線を指定できる。配線より背面に描かれる。電気的な意味を持たないので、ネットリスト・検証・部品表・電線リストのどれにも出てこない
- **電線品番凡例ブロック**: 自動描画の表(回路図タブ→配線グループ→「電線品番凡例」、クリックで配置)。そのシートの配線を線色・sq・電線品番・使用長合計の列で1行にまとめ、線色→線径の順に並べ、末尾の列に使用長合計を出す。中身は持たず、描画のたびにシートの配線から導出する(品番の引き当ては電線リストと同じ規則: ワイヤ自身の品番を優先し、無ければプロジェクトの電線品番表を引く)。配線の無いシートでも列見出しだけは描く。固定の2.0mm文字・黒の罫線・塗りなし。他のエンティティと同じく配置・移動・削除ができ、電気的な意味を持たないので図形と同じくネットリスト・検証・電線リストのどれにも出てこない([配線管理](05-wire-management.ja.md)参照)
- **回路マクロ**: 選択範囲を再利用できるマクロとして保存(名前・カテゴリ・基準点=選択範囲の左下ピン・バリアント`A`)し、`~/MadakeCAD/macros`へ置く。部品挿入ダイアログの**マクロ**タブから挿入でき、配置中はゴースト表示・`R`で回転・`Tab`でバリアント切替。挿入時に参照記号はプロジェクトで使用済みの最大番号の次から自動再採番され、線番はクリアされるので、同じシートへ2回落としても衝突しない。`⌘C`/`⌘V`のコピー&ペーストも同じ仕組み(無名マクロ)。挿入1回=編集1回なので`⌘Z`一発で回路ごと戻せる
- **マクロの値セット**: マクロは**プレースホルダ**(「モータ定格」「ヒューズ型番」のような名前付きの枠。マクロ内の特定のエンティティの型番/値または属性`attrs.<名前>`を指す)を持てて、その全部をまとめて埋める**値セット**をいくつでも用意できる。保存ダイアログにプレースホルダ表と値セット表が出て、値セットを持つマクロだけ挿入ダイアログに値セットのドロップダウンが出る。回路を落とす前に「400V/5.5kW」を選べば、含まれるシンボルの定格や型番が一括で入る(それでも**undo一発**)。`⌘C`/`⌘V`の無名マクロには値セットが無く、これらの項目が無い古いマクロファイルもそのまま読める。知らないプレースホルダや存在しないエンティティを指す値セットは、図面を一切変えずにエラーになる
- **コイル⇔接点クロスリファレンス**: 同じ参照記号を持つシンボル(`K1`のコイルとその接点群)は1つのデバイスとして扱われる。コイルの下に接点マップ(IEC 60947-1の端子対`13-14`・`23-24`…と各接点の`/シート.ゾーン`)を描き、各接点の脇にはコイルの所在を出す(右→上→下の順で、その場に既にある配線注記と重ならない側を選ぶ)。部品の接点構成(`contact_config`、例`2NO+2NC`)が分かるときは未使用接点が`—`で並び、実装数を超えて使うとERCエラーになる
- **実機ブロック表示(リレーコイル)**: コイルは既定では分散配置(小さなコイル図形+下に接点マップ)で描かれる。プロパティパネルの「実機ブロックで表示」(`attrs.device_block`)にチェックを入れると、代わりに参照記号・型番・接点イメージ(この参照記号を共有する接点ごとにIEC端子対と`/シート.ゾーン`を1行ずつ)をまとめた1つの外形として描く。どちらの表示でも接点は従来どおり個別に配置・配線されたままで、コイル自身のピンも動かないので、チェックの切替で配線が切れることはない(表そのものは常に正立で描き、コイルを回転・反転させると動くのはピンだけ。引き出し線はそのピンから、ピン自身の軸(配線が来る向き)に沿ってブロックの外形まで伸びる)。コイルはブロックの中ならどこをクリックしても選べる。接点イメージは表示クラス「参照記号」に属するので、隠すと外形とヘッダだけが残る。SVG/PDF出力も同じ外形で描く
- **デバイス単位シート間参照**: 2枚以上のシートに現れる参照記号は、そのどのインスタンスの脇にも`/2.B3`形式の注記が自動で付き、複数なら(`/2.B3 /3.C1`のように、ネットラベルのシート間クロスリファレンスと同じ1スペース区切りで)並ぶ。ネットラベルのシート間クロスリファレンスを任意のデバイスへ一般化したもの。ここで対象外になるのは、上記のコイル⇔接点クロスリファレンスが実際に所在を書いているコイル・接点だけなので、接点をどこにも持たないリレーコイル(コイル⇔接点では何も注記されない)には普通のデバイス単位参照が付く
- **プロジェクト内検索(⌘F)**: キャンバス上の浮き検索バー(参照記号/型番/ネット/テキストのフィルタチップ)と下部ドックの結果パネル(参照/種別/所在/補足)。`Enter`・`Shift+Enter`でヒットを巡回、`Esc`で閉じる。行を選ぶとシートが切り替わり、対象を選択してズームする
- **デバイスナビゲータ**: 左パネル3タブ目。参照記号ツリーを機能単位(コイル・端子対付きの接点・端子・本体)まで展開し、各機能の`/シート.ゾーン`を並べる。行クリックでジャンプ、右クリックでジャンプ/削除(削除もCommand経由なので`⌘Z`で戻る)
- **参照サーフィン(Surfer)**: 参照記号のあるシンボル・ネットラベル・線番付きワイヤをAlt(Option)+クリックすると所在一覧のポップアップが開く。↑↓と`Enter`で所在を巡回、`Esc`で閉じる
- **表示クラス(レイヤ)**: 配線/シンボル/参照記号/ネットラベル/線番/配線注記/ハーネス/図形/注記/盤/図枠/グリッドの12トグル(リボン表示タブ。画面のみで、出力には常に全要素。配線注記は図面の主情報なので常に出力される)
- **PLC I/O**: 部品DBからPLCモジュールを配置すると(`plc_module`定義が点数・入出力の向き・メーカのアドレス体系を持つ)、ピン数可変シンボル`plc_di_{n}p`/`plc_do_{n}p`として置かれる。**I/O割付表**(レポートタブ→PLC I/Oグループ)は1点=1行で、アドレス・信号名・コメントは人が編集し、接続先・線番は図面から読み取って表示する。「自動採番で埋める」は開始アドレスからモジュール1枚ぶんをその体系どおりに振る — 三菱=8進(`X0…X7, X10`)/Siemens=バイト.ビット(`%I0.0`)/Allen-Bradley=ワード/ビット(`I:0/0`)。表はCSVで往復できるので、信号名は表計算ソフトで一括入力できる。「I/O図面を生成」はラダーページ(縦の`P24`母線+1点=1ラング。各ラングにアドレスと信号名)を**undo一発**で作り、生成したページはERC指摘ゼロ。あとから図面を直す(ラングに機器を結線する・線番を振る)と、そのまま接続先・線番の列とPLC I/Oレポートへ反映される
- **プロパティパネル**: 選択物の参照記号・型番、シンボルの機能ラベルとピン表、コネクタの嵌合相手、注記の基準位置/色/太字、ネットラベルのタグ形状、ワイヤの線色・線径・長さ・電線品番(電線品番表から引けた品番はプレースホルダで表示)

## シンボルエディタ

JSONを手書きせずに自分の記号を描ける。リボン「管理」タブ→「ライブラリ」グループ→「シンボルエディタ」。

- **複製から始める**: エディタは白紙で開き、「複製して新規」のポップオーバーに同梱シンボルとユーザーシンボルが並ぶ。1つ選ぶと図形・接続点・属性スロットを引き継いだ下書き(id=`{元のid}_copy`、名前の末尾に「のコピー」)になる。保存するまでファイルには何も書かない
- **キャンバス**: 2.5mmグリッド+スナップ。線・矩形・円・弧はそれぞれドラッグ1回で描き、文字は座標バーに入れた文字列を置き、属性ツールは未配置のスロットを順に置き、接続点ツールはクリックした位置にピンを置いて向きを外形から自動で決める。クリックで選択・ドラッグで移動・`Delete`で削除。頂点編集・回転・複数選択はこの版には無い
- **属性**: モデルが持つ4種だけ — `TAG`(参照記号。必須)・`PART`・`DESC`・`RATING`。入力した値はエディタのキャンバスに描く**見本**で、シンボルのファイルには残らない
- **接続点**: 番号/方向/名前の表と「+上・+下・+左・+右」ボタン。点はグリッドの交点に乗っている必要がある。離れた2点に同じ番号を振るのは正しい使い方(貫通端子)で、同じ点での重複は誤り
- **回転バリアント**: 0°/90°/180°/270°を図面と同じ描画で並べる。バリアントは保存せず自動で導出する(端子番号も属性の位置も回転に追従する)
- **保存前チェック**: 先頭4行(グリッド/番号の重複/必須属性/任意属性)は固定で、それ以外の指摘は後ろに続く。任意属性の未配置は注意止まりで保存できる。最終的な可否はRust側が決めるが判断は同じコードなので、画面で通ったものは保存でも通る
- **保存先**: `~/MadakeCAD/symbols/{id}.json`(`SymbolDef`のJSONそのまま)。分類は必ず「ユーザー」。同梱シンボル・ピン数可変シンボルとidがぶつかるものは拒否する(あとから置いたファイルが既存図面の見た目を黙って変えないため)。拒否されたときは**何も書かず**、理由を全部返す。保存した記号は部品挿入ダイアログの「ユーザー」カテゴリにすぐ出る
- **ライブラリ追従**: 図面はシンボルidだけを持つので、ユーザーシンボルを保存し直すと**すでに置いてある部品も新しい定義で描き直される**。使用中のシンボルの削除は強制指定なしでは拒否し、何台使われているかを返す
- UI以外からも: IPC・`GET /api/v1/symbols/user`・`POST /api/v1/symbols/user/save|delete`・`POST /api/v1/symbols/duplicate`、MCPツール`duplicate_symbol`/`save_user_symbol`/`delete_user_symbol`(AIアシスタントも記号を作れる)

## 2D盤レイアウト

盤の中身を描くもう1種類のシート。図面タブ行の**+**が種別(回路図/盤レイアウト)を聞き、盤シートを開くとリボンは「パネル」タブへ、左パネルは「未配置部品」へ自動で移る。

- **盤のエンティティ**: 盤枠(外形と、外周から10mm内側の取付板。1つのエンティティなので必ず一緒に動く)・DINレール(水平。押し始めた高さが取付線で、TS35相当の35mm帯として描く)・配線ダクト(45°のハッチ。斜線は用紙座標に固定してあるので隣り合うダクトでも線がそろう)・フットプリント(部品が盤面で占める矩形)・凡例表。いずれもふつうのエンティティなので、`⌘Z`・移動・削除が回路図と同じように効く
- **未配置部品**: 回路図にあってどの盤シートにもフットプリントが無い参照記号(リレーのコイルと接点は1台として数える)。行には参照記号・型番・外形寸法と、その寸法の出どころ(部品DBの外形/寸法から自動/未登録)が出る。行をクリックしてから盤面をクリックすると置ける。ゴーストは**部品の中心**を持ち、`R`で90°回り、レール帯の中なら中心が取付線へ吸い付く。置いたあとの移動も同じように吸い付き、`⌘Z`一発で戻る
- **バルーン(アイテム番号)**: 「バルーン採番」でそのシートのフットプリントへ読み順に1〜Nを振り、バルーンを描く。読み順の段は部品の**中心の高さ**で分け、段の中は左から右。BOMの先頭列がこのアイテム番号なので、配置表とBOMは必ず一致する。逆コマンドが採番前の番号を戻すので、採番もundo一発
- **凡例表**: 置き場所だけを持つエンティティで、行は描画のたびに同じシートのフットプリントから導出する(内容が古くなることがない)
- **盤の検査**(「間隔チェック」で実行し、検証結果パネルに並ぶ): `panel.overlap`=面で重なるフットプリントの対(辺が触れているだけはレールに並べた普通の姿なので報告しない)/ `panel.off_rail`=どのレールにも乗っていない部品(レールを1本も描いていない盤では、取付板への直付け設計とみなして報告しない)/ `panel.rail_fill`=レールごとの充填率(部品の幅の合計÷レール長。80%超は注意)/ `panel.orphan_footprint`=回路図に無い参照記号のフットプリント
- **盤内部品配置表**: アイテム番号/参照記号/型番/X/Y/レールの6列を、CSV・図枠付き図面シート・PDF一括のいずれでも出せる。X/Yは描かれる外形の左上角で、レール番号は盤の上から順
- 盤シートは配線を持たないのでERC・電気検証の対象外
