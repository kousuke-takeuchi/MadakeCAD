# MadakeCAD 規格・慣習ノート

MadakeCADに同梱される作図知識。エージェントのシステムプロンプトへ毎ターン注入される。
図面を描く・直す・レビューするときは、迷ったらこのノートの決まりに従うこと。
プロジェクト固有の流儀は、設定「エージェント > 知識ファイル」で指定したMarkdownが
このノートの後ろに追記される(後ろの記述が優先)。

**書いていないことは推測しない。** 規格の条項番号・細かい数値を思い出せないときは、
「規格で確認が必要」と断ること。もっともらしい条項番号を創作してはならない。

## 1. 図記号 (JIS C 0617 / IEC 60617)

- 電気用図記号の日本産業規格はJIS C 0617シリーズで、国際規格IEC 60617に整合している。
  MadakeCADのシンボルライブラリはこの系統の形状に従う。
- 使えるシンボルIDは`list_symbols`で確認する。第一版の主なもの:
  `resistor` / `capacitor` / `diode` / `led` / `fuse` / `switch_spst` / `pushbutton_no` /
  `relay_coil` / `relay_contact_no` / `lamp` / `motor` / `battery` / `ground` / `terminal`。
  極数可変の動的IDとして`connector_{n}p` / `terminal_block_{n}p`(n=1..50)が使える。
- **接点は非励磁・非操作の状態で描く**(リレーが動いていない、ボタンを押していない状態)。
  a接点(メーク接点)は開いた形、b接点(ブレーク接点)は閉じた形で描くのが図記号の約束。
- **リレーはコイルと接点を離して描いてよい**。コイル(`relay_coil`)と接点
  (`relay_contact_no`)には同じ参照記号(例: K1)を付ける。これは重複ではなく、
  MadakeCADの検証も同一参照として許容する(どのコイルの接点かを参照記号で辿る)。
- 電源は`battery`(値= 電圧。既定24V)、接地・共通線は`ground`で表す。

## 2. 参照記号(部品記号)

- 形は「種別の接頭辞 + 通し番号」(K1, K2, F1 …)。図面内で重複させない。
- MadakeCADが標準とする接頭辞(日本の制御盤の慣用):

  | 接頭辞 | 対象 |
  |---|---|
  | R | 抵抗 |
  | C | コンデンサ |
  | D | ダイオード・LED |
  | F | ヒューズ・保護機器 |
  | SW | スイッチ(切替・選択) |
  | PB | 押しボタン |
  | K | リレー・電磁接触器(コイルと接点で共有) |
  | M | モータ |
  | PL | 表示灯(パイロットランプ) |
  | TB | 端子台 |
  | J | コネクタ |
  | W | ハーネス(電線束の囲み) |
  | BT | 電池・直流電源 |

- 番号は図面の読み順(左上→右下)で振ると追いやすい。
- 参照記号を空のままにしない(検証が`erc.empty_reference`で指摘する)。
- 機器の文字コードを定める国際規格としてIEC 81346-2があるが、上記の接頭辞は
  日本の制御盤の慣用であり、IEC 81346-2の文字コードとは一致しない。
  **顧客・社内の指定がある場合はそちらが優先**(知識ファイルで上書きできる)。

## 3. 線色と線径 (sq)

- 線径は「sq」= 導体断面積(mm²)で呼ぶ。制御回路は0.3〜0.75sqが標準で、
  主回路は流れる電流で選ぶ。
- 色分けはJIS B 9960-1(IEC 60204-1)の推奨に従うのが無難:

  | 色 | 用途 |
  |---|---|
  | 緑/黄(緑と黄の2色) | 保護導体(接地)。**この配色は保護導体専用**で他に流用しない |
  | 黒 | 交流・直流の主回路(電力回路) |
  | 赤 | 交流の制御回路 |
  | 青 | 直流の制御回路 |
  | 水色(淡青) | 中性線 |
  | 橙 | 外部電源から給電される回路(インターロックなど、主電源を切っても生きている回路) |

- 現場の慣行では「制御=赤の0.3〜0.75sq、主回路=黒、接地=緑/黄」が広く使われる。
  MadakeCADの`Wire.color`は文字列(`black` / `red` / `blue` / `light_blue` /
  `green_yellow` / `orange` など)で、色とsqの組から電線品番を引く
  (`Project.wire_parts`。BOM・電線リストに載る)。
- MadakeCADの検証が使う許容電流の目安(AVS系の慣用値):

  | sq | 0.3 | 0.5 | 0.75 | 1.25 | 2.0 | 3.5 |
  |---|---|---|---|---|---|---|
  | 許容電流 A | 7 | 9 | 12 | 16 | 22 | 33 |

  これを超えると`elec.wire_ampacity`(エラー)になる。電圧降下は電源電圧の3%を
  超えると`elec.voltage_drop`(警告)。

## 4. 線番・ネットラベル・クロスリファレンス

- **線番はネット単位**の番号。電気的に繋がった配線(ネット)の全ワイヤに同じ番号を書く。
  端子台やコネクタで切れていない限り、1ネット=1線番。
- 自動採番は`execute_commands`の`renumber_wires`で行う。
  - `mode=append`: 既存の線番・ネットラベルを残し、未採番のネットにだけ追い番を振る(通常はこれ)
  - `mode=renumber`: 数字の線番を捨てて振り直す(手で付けた名前は残る)
  - `start`で開始番号、`sheet_id`省略で図面全体。採番順は「上→下、同じ高さなら左→右」で決定的
- **ネットラベル付きのネットには線番を振らない**。ラベル名(例: `24V`, `0V`, `24-P1`)が
  そのままネット名になる。電源・接地・シートを跨ぐ信号にはネットラベルを付ける。
- 同名のネットラベルはシートを跨いで論理的に接続される。1つのネットに異なる名前の
  ラベルが2つ付くと異電位の直結とみなされ`erc.label_conflict`(エラー)になる。
- SVG/PDF出力では、シートを跨ぐネットラベルに`/2.B3`形式(= シート2のゾーンB3)の
  クロスリファレンスが自動で付く。
- 参考規格: 電線・心線の識別表示はIEC 62491、図面作成の規則(表現・参照)はIEC 61082-1。

## 5. ハーネス

- まとめて製作・購入する電線束の範囲を破線の囲み(IEC 61082-1のグループ囲み)で示す。
- 追加は`execute_commands`の`add_entity`で`kind="harness"`(矩形4点・`name`・`note`)。
  名前はW1, W2 …。囲みに幾何学的に入っている配線がその束に属し、電線リストの
  ハーネス列に載る。

## 6. 座標系・グリッド・レイアウト

- 用紙座標系はmm単位・**左上原点・Y下向き**。用紙はISO A列(A4/A3/A2…)。
- **グリッドとピンピッチは2.5mm**。シンボルのピンと配線の端点は必ず2.5mmの
  格子点に載せる(0.1mmでもずれると接続と判定されない)。
- 回転は0/90/180/270のみ。斜めの配線は使わず、水平・垂直のセグメントで描く。
- 回路は左から右へ、電源は上・接地は下に置く。制御回路(ラダー)は左右の母線の間に
  1回路ずつ横に並べ、動作順に上から下へ積む。
- **交差は接続ではない**。接続する交点には必ずジャンクション(`kind="junction"`)を置く。
  無いと`erc.dangling_wire`になる。
- シンボル同士は最低5mm(2グリッド)離す。参照記号・型番はシンボル外形の上端側へ
  自動配置されるため、上に5mm程度の余白を見込む。
- 図枠(JIS Z 8311)は表題欄が右下、改訂欄はその直上に古い改訂から下へ積む
  (最新が最上段。ISO 7200)。図枠の周囲のゾーン番号がクロスリファレンスの座標になる。

## 7. MadakeCADでの作図手順(標準フロー)

1. **現状把握**: `get_project`でシート・エンティティを、`list_symbols`で使えるシンボルIDを確認する
2. **部品配置**: `place_symbol`(またはまとめて`execute_commands`)。参照記号を必ず付け、
   2.5mmグリッド上に置く
3. **配線**: `draw_wire`で水平・垂直に引く。端点はピン座標へぴったり合わせる。
   3本以上が集まる点にはジャンクションを置く
4. **ネットラベル**: 電源・接地・シート跨ぎの信号にラベルを付ける
5. **線番採番**: `renumber_wires`(`mode=append`)で未採番ネットに線番を振る
6. **検証**: `run_verification`でエラー0を確認する(残っていれば直して再検証)
7. **出力**: 必要に応じて`export_svg` / `export_pdf` / `export_report`

## 8. 検証の指摘(Diagnostic)の読み方

| code | severity | 意味と典型的な直し方 |
|---|---|---|
| `erc.unconnected_pin` | 警告 | ピンがどこにも繋がっていない。配線するか、未使用が正しいなら理由を説明する |
| `erc.empty_reference` | 警告 | 参照記号が空。接頭辞+通し番号を付ける |
| `erc.duplicate_reference` | エラー | 参照記号の重複(リレーのコイル+接点は除く)。番号を振り直す |
| `erc.dangling_wire` | 警告 | 配線の端点が宙に浮いている、またはジャンクション無しで他の配線の途中に乗っている |
| `erc.label_conflict` | エラー | 1つのネットに異なるネットラベル(異電位の直結)。配線かラベルを直す |
| `elec.unreachable_load` | 警告 | 負荷まで電源が届いていない(スイッチ・ヒューズの経路断) |
| `elec.wire_ampacity` | エラー | 電線の許容電流を超えている。sqを上げる |
| `elec.voltage_drop` | 警告 | 電圧降下が電源電圧の3%超。sqを上げるか経路を短くする |
| `elec.fuse_rating` | 警告 | ヒューズ定格と負荷電流・電線許容電流の整合が取れていない |
| `elec.no_current_attr` | 情報 | 負荷に`current_a`属性が無く電流計算を省いた。分かるなら属性を入れる |
| `elec.approximate_mode` | 情報 | ngspice未導入のためグラフ近似で判定した |

情報(info)は放置してよい。**エラーは必ず0にする**。警告は理由を説明できるものだけ残す。
